## 一、架构概览

### 1.1 项目定位

SAAS-APP 是一个**配置式装修电商 SaaS 高保真原型**，面向三类终端用户：

| 终端 | 路由前缀 | 目标用户 | 入口HTML |
|------|----------|----------|----------|
| APP端（移动端） | `/app/` | C端消费者 | `app.html` |
| 运营后台（PC） | `/admin/` | SAAS平台运营人员 | `admin.html` |
| 租户后台（PC） | `/tenant/` | 租户（商家）管理员 | `tenant.html` |

### 1.2 技术栈

| 层 | 技术 | 版本 | 用途 |
|----|------|------|------|
| 框架 | Vue 3 | ^3.4.21 | 组合式API + `<script setup>` |
| 语言 | TypeScript | ^5.4.3 | 全量类型安全 |
| 构建工具 | Vite 5 | ^5.2.6 | 多入口构建（admin/tenant/app） |
| 路由 | Vue Router 4 | ^4.3.0 | Hash 模式，单一事实源 |
| 状态管理 | Pinia 2 | ^2.1.7 | 3 Store + localStorage 持久化 |
| UI 组件库 | Element Plus | ^2.6.3 | 后台管理界面 |
| 数据校验 | Zod 3 | ^3.22.4 | 契约层 Schema 校验 |
| 端到端测试 | Playwright | ^1.62.1 | UC覆盖率/Tab切换/用户流测试 |

### 1.3 五层架构

```
┌──────────────────────────────────────────────────────┐
│  页面层 (pages/)  — 31个 .vue 页面                    │
│  app/ + admin-app/ + tenant-app/                     │
├──────────────────────────────────────────────────────┤
│  组件层 (components/) — 19个 .vue 组件               │
│  app/ + admin/ + use-case-card/                     │
├──────────────────────────────────────────────────────┤
│  状态层 (stores/) — 3个 Pinia Store                  │
│  app-config-store + project-store + user-store      │
├──────────────────────────────────────────────────────┤
│  服务层 (services/) — data-service.ts                │
│  localStorage CRUD + 序列化/反序列化/导入/导出/重置    │
├──────────────────────────────────────────────────────┤
│  契约层 (contracts/) — Zod Schema + 类型导出         │
│  schemas/ + api/ + state-machine/ + index.ts         │
└──────────────────────────────────────────────────────┘
         ↑ 数据源层 (data/) — use-cases/ (3端UC数据源)
```

**依赖规则**：页面层 → 组件层 → 状态层 → 服务层 → 契约层（单向依赖，契约层不可反向依赖任何上层）

## 二、多入口构建架构

### 2.1 Vite 多入口配置

```typescript
// vite.config.ts
build: {
  rollupOptions: {
    input: {
      admin: resolve(__dirname, 'admin.html'),   // 运营后台
      tenant: resolve(__dirname, 'tenant.html'),  // 租户后台
      app: resolve(__dirname, 'app.html'),        // APP端
    },
  },
}
```

### 2.2 入口文件映射

| 入口HTML | 入口TS | 默认路由 | 容器组件 |
|----------|-------|----------|----------|
| `app.html` | `main-app.ts` | `#/app/home` | `MobileFrame` (5 Tab) |
| `admin.html` | `main-admin.ts` | `#/admin/search` | `AdminLayout` (左侧菜单5项) |
| `tenant.html` | `main-tenant.ts` | `#/tenant/projects` | `TenantLayout` (左侧菜单6项) |
| `index.html` | `main.ts` | `#/` → `/app/home` | 默认重定向 |

### 2.3 路由模式

- **Hash 模式** (`createWebHashHistory`)：适用于静态部署（EdgeOne Pages），无需服务端配置
- **单一事实源**：`src/router/index.ts` 是所有路由的唯一定义点
- **懒加载**：所有页面组件使用 `() => import()` 动态导入，按需加载

## 四、状态层架构（Pinia 3 Store）

### 4.1 Store 分域设计

| Store | localStorage Key | 管理域 | 对应ENT实体 |
|-------|------------------|--------|-------------|
| `app-config-store` | `saas:app-config` | APP运营配置 | AdBanner/KingKongEntry/HotWord/CustomSearchResult/RecommendItem |
| `project-store` | `saas:project` | 项目域数据 | Project/Store/Product/LiveRoom/MemberLevelConfig/ProjectMember/ProjectHomeConfig/Tenant/MarketingCategory/Coupon/SignInState |
| `user-store` | `saas:user` | 用户域数据 | AppUser/AppMessage/ShippingAddress |

### 4.2 持久化机制

```
后台修改 → Pinia ref 变更 → watch(deep) 触发 → dataService.save() → localStorage 写入
                                                                    ↓
APP端读取 ← Pinia computed ← dataService.load() ← localStorage 读取（页面刷新后）
```

**关键设计**：
- 每个 Store 在初始化时从 localStorage 读取数据（`dataService.loadXxx()`）
- 每个 ref 通过 `watch(ref, (newVal) => dataService.saveXxx(newVal), { deep: true })` 自动同步
- `safeGet/safeSet` 包裹 try-catch，防止 localStorage 读写异常导致崩溃
- 数据迁移：旧版数据结构自动迁移（如推荐规则从单规则迁移到多维度排序链）

### 4.3 推荐引擎架构（核心业务逻辑）

推荐引擎采用**多维度排序链**模式（v3.1.10 重构）：

```typescript
// 排序维度
interface SortDimension {
  dim_type: 'live_status' | 'view_count' | 'anchor_type' | 'project'
          | 'product_category' | 'sales_count' | 'listed_time';
  direction: 'asc' | 'desc';
  selected_values: string[];  // 多选值，支持拖拽排序优先级
}

// 推荐规则
interface RecommendRule {
  sort_dimensions: SortDimension[];  // 多维度叠加排序（ORDER BY 语义）
}

// 推荐项
interface RecommendItem {
  item_id: string;
  item_type: 'live' | 'product';
  sort_order: number;    // 手动推荐排序值（越小越靠前）
  is_default: boolean;   // 是否默认规则
  display_limit: number; // 首页展示条数（默认6）
  updated_by: string;
  updated_at: string;
}
```

**叠加模式**（v3.1.8 重构）：
1. 手动推荐在前（按 `sort_order` 升序）
2. 默认规则结果去重补足至总数上限
3. 精选Tab不受 `display_limit` 限制，显示所有可见项

## 十一、架构决策记录（ADR）

### ADR-001: Hash 路由 vs History 路由

**决策**：采用 Hash 路由（`createWebHashHistory`）

**理由**：
- 静态部署（EdgeOne Pages）无需服务端 rewrite 配置
- 避免 SPA 刷新 404 问题
- 多入口构建下各入口独立路由空间

### ADR-002: Pinia + localStorage 持久化

**决策**：Pinia Store + `watch(deep)` 自动同步到 localStorage

**理由**：
- 原型阶段无后端，localStorage 提供数据持久化
- `watch(deep)` 实现响应式自动同步，无需手动调用
- `safeGet/safeSet` 包裹异常处理，保证健壮性
- 未来接入后端时，仅需替换 `data-service.ts` 为 API 调用

### ADR-003: 多入口构建 vs 单入口

**决策**：采用 Vite 多入口构建（admin/tenant/app 三个 HTML）

**理由**：
- 三端独立部署，各自加载所需代码
- 减小单入口包体积
- 各端可独立访问（`app.html` / `admin.html` / `tenant.html`）

### ADR-004: 推荐引擎多维度排序链

**决策**：推荐规则从单规则重构为多维度排序链（`sort_dimensions[]`）

**理由**：
- 支持多维度叠加排序（ORDER BY 语义）
- 维度间可调整优先级
- 多选维度值支持拖拽排序
- 满足 BR-SHP-008/009/030/034/035 的多维度排序需求

### ADR-005: 项目首页搜索删除

**决策**：删除 UC-009-02（项目首页搜索），BR-SHP-029 标注 deprecated

**理由**：
- 用户确认项目首页不需要搜索入口
- 搜索功能集中在平台搜索页（UC-007/008）
- FN-009 模块从6模块精简为5模块
