## 一、问题陈述

### 核心问题
1. 一个管理页面有N个UC怎么配截图？——不能每个UC一张截图（太多），也不能不配截图（不可读）
2. 涉及状态的页面需要梳理状态操作矩阵吗？——需要，但状态操作矩阵≠状态机图
3. 需求文档给谁看？——给人看也给AI回归学习用（双读者设计）

### 解决目标
- 生成一份**正规可读的HTML需求文档**，包含真实截图、UC标注、状态操作矩阵
- 截图与用例按**三级策略组合**，10张截图覆盖17+UC（压缩率41%）
- 文档同时服务**人（可视化阅读）**和**AI（元数据回归学习）**

## 二、三级截图策略——截图与用例如何组合

### 2.1 策略概览

| 级别 | 名称 | 说明 | 数量 | 覆盖UC |
|------|------|------|------|--------|
| **L1** | 页面锚点截图 | 1张/页，整页截图+UC编号圆圈标注 | 每页1张 | 5-8个通用UC |
| **L2** | 状态增量截图 | 弹窗打开/筛选结果/按钮置灰等显著视觉变化 | 2-3张/页 | 3-5个状态UC |
| **L3** | UC特写 | 按需，hover态/tooltip等细节 | 0-1张/页 | 1-2个细节UC |

### 2.2 L1锚点截图标注方式

L1截图上**标注UC编号圆圈**，指向对应UI元素：

```
┌─────────────────────────────────────────────┐
│  智能擦除配置                                │
│                                             │
│  ①搜索框  ②类型筛选    [创建擦除模板⑤]      │
│                                             │
│  ┌───────────────────────────────────────┐  │
│  │ 模板名称  擦除类型  音频处理  操作    │  │
│  │ 默认模板  不合规    静音     ③编辑④删除│  │
│  └───────────────────────────────────────┘  │
│                            ⑥创建时间排序     │
└─────────────────────────────────────────────┘

① = UC-006-06 搜索擦除模板
② = UC-006-07 按类型筛选
③ = UC-006-09 编辑擦除模板
④ = UC-006-10 删除擦除模板
⑤ = UC-006-03 创建擦除模板
⑥ = UC-006-08 按创建时间排序
```

### 2.3 截图位置组织

| 位置 | 说明 |
|------|------|
| **锚点内联** | L1截图放在页面用例描述旁边，内联展示 |
| **增量就近** | L2截图放在对应UC的备选流程描述旁边 |
| **附录索引** | 所有截图在文档末尾有索引表（UC编号↔截图文件↔页面↔状态） |

### 2.4 实际效果

S2实践验证：10张截图覆盖17个UC（压缩率41%），比每个UC一张更高效。

## 三、状态操作矩阵

### 3.1 触发条件

实体≥2种状态且UI行为不同时**必须包含**状态操作矩阵。

### 3.2 格式

当前状态 × UI元素 × 可用操作 × 关联截图 × 关联UC × 关联BR

### 3.3 示例（审核处置页）

| 当前状态 | UI元素 | 可用操作 | 关联截图 | 关联UC | 关联BR |
|---------|--------|---------|---------|--------|--------|
| pending | 处置按钮 | 可点击→打开处置弹窗 | ac-007-01 | UC-007-05 | BR-007 |
| pending | 断流选项 | 可选择→二次确认 | ac-007-02 | UC-007-09 | BR-007 |
| disposed | 处置按钮 | **置灰disabled** | ac-007-03 | UC-007-05 | BR-007 |
| disposed | 断流选项 | 不可见 | — | — | — |

### 3.4 关键区分

**状态操作矩阵 ≠ 状态机图（五图之一）**
- 状态机图：描述实体状态转换（业务维度）
- 状态操作矩阵：描述页面UI元素在不同状态下的可用性（操作维度）
- 矩阵是**页面操作维度的人机双读交叉视图**

## 六、工作流集成（V1.0.0关键调整：截图时机改为close）

### 6.1 原方案 vs 调整后

| 维度 | 原方案（2026-07-18讨论） | V1.0.0调整 |
|------|----------------------|-----------|
| 截图时机 | QA测试阶段 | **close阶段**（用户决策） |
| 原因 | — | QA非最终状态会有调整，close时代码已冻结 |
| 截图时效 | 可能过时 | **永不过时**，版本最终态 |
| 版本快照 | 截图不在快照中 | **截图归入版本快照**，永久可回溯 |

### 6.2 调整后的close流程

```
AC验收 → handoff → 【新增：生成HTML需求文档（含真实截图+UC标注+状态矩阵）】 → 版本快照 → 差异报告 → 版本沉淀 → 大脑进化
```

HTML需求文档在**handoff之后、版本快照之前**生成：
- handoff已完成 → 代码最终态确认
- 版本快照时 → HTML文档+截图一起归档
- 差异报告时 → 可引用HTML文档中的截图对比

### 6.3 生成步骤

```
Step 1: 启动dev server（如未运行）
Step 2: 解析PRD → 提取页面清单 + UC清单 + 状态机
Step 3: 逐页面截图
  ├─ L1: 整页截图（default状态）→ 标注UC编号圆圈
  └─ L2: 触发状态变化后截图（弹窗/筛选/置灰等）
Step 4: 生成状态操作矩阵（有状态变化的页面）
Step 5: 生成HTML需求文档
  ├─ PRD用例说明（人可读）
  ├─ 截图内联（带UC标注）
  ├─ 状态操作矩阵（HTML表格）
  └─ AI元数据注释（HTML注释，AI可读）
Step 6: 保存到 docs/09-versions/v{version}/prd-html/
Step 7: 纳入版本快照
```

  type: "hard_gate"
  name: "HTML需求文档完整性（含截图+UC标注+状态矩阵）"
