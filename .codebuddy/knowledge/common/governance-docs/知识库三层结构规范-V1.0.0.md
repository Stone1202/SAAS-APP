# 知识库三层结构规范 V1.0.0

> **创建日期**：2026-07-21
> **定位**：定义知识库的三层结构，明确各层边界、加载优先级和维护责任
> **核心原则**：全局共享 > 项目共享 > 个人工作过程

---

## 一、三层结构总览

```
┌─────────────────────────────────────────────────────┐
│ Layer 1: 全局共享知识库（common/ + domains/）         │
│   所有项目、所有成员共享                               │
│   管理员维护，成员只读                                 │
├─────────────────────────────────────────────────────┤
│ Layer 2: 项目共享知识库（projects/{project}/）        │
│   同一项目的所有授权成员共享                           │
│   项目成员维护，管理员审核                             │
├─────────────────────────────────────────────────────┤
│ Layer 3: 个人工作过程（Git commits + branches）       │
│   成员个人的开发过程记录                               │
│   成员个人维护，不进入知识库                           │
└─────────────────────────────────────────────────────┘
```

---

## 二、Layer 1：全局共享知识库

### 2.1 目录结构

```
.codebuddy/knowledge/
├── common/              ← 跨项目共享规范+经验库
│   ├── gates-registry.yml         ← 门禁注册中心
│   ├── iron-rules-registry.yml    ← 铁律注册中心
│   ├── doc-standards.yml          ← 文档规范
│   ├── metrics-standards.yml      ← 行业指标标准
│   ├── brain-memory-spec.yml      ← 大脑记忆规范
│   ├── api-learner.yml            ← API学习公共定义
│   ├── flow-standards/            ← 流程规范子目录
│   ├── arch/ ux/ ba/ qa/ ops/     ← 各Agent专业知识库
│   ├── 经验库/                    ← 跨项目经验库（3个文件）
│   │   ├── 最佳实践库.md
│   │   ├── 踩坑避雷库.md
│   │   ├── Review模式库.md
│   │   └── _pending/              ← 待管理员审核的经验
│   ├── governance-docs/           ← 治理文档
│   ├── audit-reports/             ← 审计报告
│   └── 流程改进待办.yml            ← 流程改进待办清单
├── domains/             ← 领域知识库（48注册/8已学）
│   ├── DOMAIN-INDEX.yml
│   ├── account/ ai/ design/ thirdparty/ ...
└── coding/ rules/       ← 编码规范+业务规则
```

### 2.2 内容范围

| 类型 | 内容 | 维护者 | 加载时机 |
|------|------|--------|---------|
| 流程规范 | workflow.yml / agent.md / skill.yml | 管理员 | 每次命令执行时 |
| 治理文档 | 门禁/铁律/红线/操作手册 | 管理员 | 流程变更时 |
| 跨项目经验 | 最佳实践/踩坑/Review模式 | 管理员审核 | /init时priority=5 |
| 领域知识 | 第三方API/行业标准 | 管理员学习 | BA需求分析时 |
| 流程改进待办 | _pending建议汇总 | 管理员审核 | /review-process-improvements时 |

### 2.3 维护规则

- **管理员独占写权限**：common/ 和 domains/ 下所有文件仅管理员可修改
- **成员只读**：成员通过流程自动加载，不可手动修改
- **经验提升机制**：项目经验 → `_pending/` → 管理员审核 → 提升为全局经验
- **版本管理**：重大变更走 governance-audit.yml 全局检查

## 三、Layer 2：项目共享知识库

### 3.1 目录结构

```
.codebuddy/knowledge/projects/{project}/
├── project-knowledge-v{version}.yml   ← 项目知识元数据
├── business-topology.json             ← 业务拓扑
├── 需求文档/                           ← /learn-project 产出
│   ├── {项目}-超级需求文档-PRD-v{version}.md
│   ├── {项目}-PRD-v{version}-index.md
│   └── {项目}-PRD-v{version}-vol{N}-*.md
├── 学习报告/                           ← /learn-project 产出
│   └── {项目}-学习报告-v{version}.md
├── 外部连接资产/                       ← /learn-project 产出（如有）
├── 版本沉淀/                           ← /close 后 knowledge-sedimentation 产出
│   ├── VERSION-INDEX.yml
│   └── {version}/
│       ├── 沉淀摘要.md
│       ├── 需求沉淀/
│       ├── Review沉淀/
│       │   └── REV-SUMMARY-v{version}.md  ← V5.3.0合并报告
│       ├── 大脑记忆/
│       ├── 经验教训/
│       └── 追溯链/
├── 经验/                               ← V5.3.0 项目级经验
│   ├── 最佳实践-项目级.md
│   ├── 踩坑避雷-项目级.md
│   └── Review模式-项目级.md
└── 大脑记忆/                           ← 各Agent大脑记忆latest
    └── latest/
```

### 3.2 内容范围

| 类型 | 产出命令 | 加载时机 | 维护者 |
|------|---------|---------|--------|
| 项目知识元数据 | /learn-project | /init stage-00 | 项目成员 |
| 已学PRD | /learn-project | /init stage-00 + brainstorm | 项目成员 |
| 版本沉淀 | /close 自动 | /init stage-00 priority=3 | PM Agent |
| 项目级经验 | /close 自动 | /init stage-00 priority=4 | PM Agent |
| 大脑记忆 | /close 自动 | /init stage-1 | PM Agent |

### 3.3 维护规则

- **项目成员共享**：同一项目的所有授权成员（accessible_projects）可读写
- **跨项目隔离**：成员只能访问授权的项目知识库
- **经验分层**：项目级经验直接写入，跨项目级经验经管理员审核提升
- **版本管理**：VERSION-INDEX.yml 记录所有版本沉淀

## 四、Layer 3：个人工作过程

### 4.1 内容范围

| 类型 | 存储位置 | 说明 |
|------|---------|------|
| Git commits | Git历史 | 代码变更记录 |
| Git branches | Git分支 | 功能分支/修复分支 |
| 开发日志 | projects/{project}/.codebuddy/journal/ | 对话日志/问题台账 |
| 大脑活动日志 | projects/{project}/.codebuddy/journal/brain-activity-log.md | AI推理过程 |

### 4.2 维护规则

- **成员个人维护**：不进入知识库，仅作为开发过程记录
- **Git管理**：通过 Git 提交记录变更历史
- **不加载**：不作为知识库加载对象，仅用于回溯
- **清理策略**：journal/ 在版本沉淀后可归档，不删除

## 五、加载优先级

`/init` 时的知识库加载优先级（从高到低）：

| 优先级 | 层级 | 来源 | 说明 |
|--------|------|------|------|
| 1 | Layer 2 | 跨版本传递PBL | 必须处理（上一版本未闭环反馈） |
| 2 | Layer 2 | 版本沉淀Review经验 | 上一版本Review提炼 |
| 3 | Layer 2 | 已学PRD | /learn-project产出 |
| 4 | Layer 2 | 项目级经验 | /close产出的项目级经验 |
| 5 | Layer 1 | 跨项目经验库 | common/经验库/ |
| 6 | Layer 1 | 领域知识 | domains/（关键词+AI语义匹配） |

## 六、经验提升闭环

```
项目执行 → /close版本沉淀
  ↓
项目级经验 → projects/{project}/经验/（直接写入）
  ↓
跨项目级经验 → common/经验库/（直接追加）
  ↓
流程改进建议 → common/经验库/_pending/（待审核）
  ↓
管理员 /review-process-improvements
  ↓
审核通过 → 流程升级方案 → 应用到流程引擎
审核拒绝 → 标注原因 → 归档
```

---

## 七、与V1.2.0项目隔离的关系

- V1.2.0架构：`projects/{project}/`（项目隔离，非owner隔离）
- 授权机制：`.access-control.yml` 中 `accessible_projects` 列表
- 成员可跨项目：一个成员可被授权访问多个项目
- 知识不绑定人：知识属于项目，不属于个人
