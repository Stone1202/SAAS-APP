# 成员操作手册（V1.1.0）

> **适用对象**：使用 CodeBuddy + POM 流程的团队成员
> **前置条件**：方案已实施完成，管理员已完成基础配置
> **版本**：V1.1.0 | **日期**：2026-07-21
> **V1.1.0变更**：新增多项目管理 + Git协作详细操作 + 反馈提交方式

---

## 一、角色说明

| 角色 | 谁来担任 | 做什么 |
|------|---------|--------|
| **管理员** | Jojo | 维护流程引擎、注册成员、审核知识库、管理部署、收集反馈 |
| **技术成员** | 开发/产品技术 | 使用 CodeBuddy 命令走完整 POM 流程，开发自己的项目 |
| **产品成员** | 产品/运营/设计 | 不使用 CodeBuddy，只通过链接查看部署的高保真原型 |

## 二、技术成员操作说明

### 2.1 首次入驻（一次性）

#### 管理员先做

```
步骤1：注册成员（编辑 .access-control.yml + PROJECT-INDEX.yml）
步骤2：创建 EdgeOne 访问账号
步骤3：通知成员：Git 仓库地址 + 访问门户账号密码
```

#### 成员做

```bash
# 1. 克隆工作空间
git clone https://your-git-repo/pom-workspace.git
cd pom-workspace

# 2. 配置 Git 身份
git config user.name "zhangsan"
git config user.email "zhangsan@example.com"

# 3. 打开 CodeBuddy，开始使用
# AI 自动识别你的身份（通过 git user.name 匹配 .access-control.yml）
```

### 2.2 多项目管理（V1.1.0新增）

一个成员可以同时负责多个项目。每个项目有独立的目录、端口、数据库。

#### 创建第二个项目

```bash
# 场景：张三已有 erp-portal，现在要新建 crm-portal

# 1. 联系管理员在 PROJECT-INDEX.yml 注册新项目
#    管理员会分配：新端口（如4002）+ 新数据库名（zhangsan-crm-portal-sim）

# 2. 启动新项目需求流
/init --project=crm-portal --type=新增 --desc=CRM门户v1.0

#    → ensure-project.sh 自动创建骨架：
#      projects/zhangsan/crm-portal/
#      ├── .env.development（VITE_DEV_PORT=4002, VITE_PROJECT_ID=zhangsan-crm-portal）
#      ├── .env.sim（VITE_PROJECT_ID=zhangsan-crm-portal）
#      ├── vite.config.ts（端口读环境变量）
#      └── src/adapters/sim/db.ts（数据库名 zhangsan-crm-portal-sim）

# 3. 新项目独立运行，不影响已有项目
```

#### 项目切换

```bash
# 成员可以同时开发多个项目，通过 --project 参数切换

# 开发 erp-portal
cd projects/zhangsan/erp-portal
npm run dev                    # → localhost:4001（erp-portal）

# 开发 crm-portal（另一个终端窗口）
cd projects/zhangsan/crm-portal
npm run dev                    # → localhost:4002（crm-portal）

# 执行命令时通过 --project 指定操作哪个项目
/init --project=erp-portal --type=迭代 --desc=...
/test --project=crm-portal
/close --project=erp-portal
```

#### 多项目数据隔离

| 项目 | 开发端口 | IndexedDB数据库名 | 部署路径 |
|------|---------|------------------|---------|
| erp-portal | 4001 | zhangsan-erp-portal-sim | /zhangsan/erp-portal/{version}/ |
| crm-portal | 4002 | zhangsan-crm-portal-sim | /zhangsan/crm-portal/{version}/ |

- 不同项目的浏览器数据完全隔离（不同的 IndexedDB 数据库）
- 同一项目的不同版本数据自动延续（版本升级不丢数据）
- 部署到 EdgeOne Pages 后通过路径路由区分

### 2.3 日常开发流程

#### 场景A：新项目从零开始

```
步骤1：学习项目需求（如有现有文档）
  /learn-project --project=erp-portal --source=local-dir:./需求文档

步骤2：学习领域知识（可选，贡献到共享知识库）
  /learn-domain --category=trade --name=交易通用 --source=http-url:https://...
  → 产出存入 knowledge/domains/_pending/（待管理员审核）

步骤3：启动需求流
  /init --project=erp-portal --type=新增 --desc=ERP门户v1.0

步骤4：走完 POM 流程
  需求(BA) → 设计(UX) → 架构(Arch) → 开发(FD) → 测试(QA) → 验收(AC) → handoff

步骤5：版本冻结 + 自动部署
  /close --project=erp-portal
  → 自动构建 + 部署到 EdgeOne Pages + 输出访问链接

步骤6：提交代码（见 2.4 Git协作）
```

#### 场景B：迭代已有项目

```
/init --project=erp-portal --type=迭代
→ CodeBuddy 自动加载上一版本沉淀 + 经验库
→ 继续 POM 流程... → /close → 自动部署 v2.0.0
```

#### 场景C：修复 Bug

```
/init --project=erp-portal --type=修复 --desc=修复客户列表分页问题
→ 跳过需求/设计/架构，直接 FD → QA → AC
→ /close → 自动部署 v1.0.1
```

### 2.4 Git协作操作（V1.1.0新增）

#### 日常工作流

```bash
# 1. 每天开始工作前：拉取最新代码
git checkout main
git pull origin main

# 2. 创建工作分支（按项目+版本命名）
git checkout -b zhangsan/erp-portal-v1

# 3. 开发（使用 CodeBuddy 命令）
# /init --project=erp-portal --type=新增 --desc=...
# ... 需求→设计→开发→测试→验收

# 4. 提交代码（只提交自己项目的文件）
git add projects/zhangsan/erp-portal/
git commit -m "feat(erp-portal): v1.0.0 需求完成

- 客户管理模块
- 统一沟通模块
- AI话术推荐"

# 5. 推送到远端
git push origin zhangsan/erp-portal-v1

# 6. 在 Git 平台创建 Pull Request
#    → 标题：feat(erp-portal): v1.0.0 需求完成
#    → 等待 CODEOWNER（张三自己）审批
#    → 合并到 main

# 7. 合并后删除工作分支
git checkout main
git pull origin main
git branch -d zhangsan/erp-portal-v1
```

#### 多项目并行开发的 Git 操作

```bash
# 场景：同时开发 erp-portal 和 crm-portal

# 为每个项目创建独立分支
git checkout -b zhangsan/erp-portal-v2    # erp-portal 迭代
git checkout main
git checkout -b zhangsan/crm-portal-v1    # crm-portal 新项目

# 分别提交（只提交对应项目的文件）
# erp-portal 分支
git checkout zhangsan/erp-portal-v2
git add projects/zhangsan/erp-portal/
git commit -m "feat(erp-portal): v2.0.0 迭代"

# crm-portal 分支
git checkout zhangsan/crm-portal-v1
git add projects/zhangsan/crm-portal/
git commit -m "feat(crm-portal): v1.0.0 新项目"

# 分别创建 PR，分别合并
```

#### 知识库贡献的 Git 操作

```bash
# 成员执行 /learn-domain 产出 → 存入 _pending/（已在 .gitignore 中，不提交）

# 成员需要通过 PR 提交知识库贡献：
# 1. 先取消 _pending/ 的 gitignore（临时）
git add -f .codebuddy/knowledge/domains/_pending/zhangsan_trade_交易通用_v1.yml

# 2. 提交 PR
git commit -m "knowledge: 贡献交易通用领域知识"
git push origin zhangsan/knowledge-trade

# 3. 创建 PR，管理员审核
#    → 管理员 /approve-knowledge 通过后，文件从 _pending/ 移到正式区
#    → 合并到 main，全员可见
```

### 2.5 反馈提交（V1.1.0新增）

成员遇到问题或有改进建议时，通过以下方式提交反馈：

#### 方式A：通过 /feedback 命令（流程内反馈）

```bash
# 在 /close 之前随时可以提交反馈
/feedback --project=erp-portal --msg="需求分析阶段缺少业务规则模板，导致BR编写不规范"
```

#### 方式B：通过 Git Issue（流程外反馈）

```
在 Git 仓库创建 Issue：
  标题：[反馈] ensure-project.sh 端口分配未检测已占用端口
  内容：
    问题描述：...
    复现步骤：...
    期望行为：...
    实际行为：...
    截图：...
  标签：feedback / bug / enhancement
```

#### 方式C：直接告知管理员

```
直接向管理员描述问题，管理员会：
  → 记录到 problem-ledger
  → 评估影响范围
  → 安排修复优先级
  → 通过 /fix 或流程调整解决
```

### 2.6 成员能做什么 / 不能做什么

#### ✅ 能做

| 操作 | 命令 |
|------|------|
| 脑暴 | `/brainstorm --brainstorm-type=regular --project=xxx` |
| 启动需求 | `/init --project=xxx --type=新增 --desc=...` |
| 学习项目 | `/learn-project --project=xxx --source=...` |
| 学习领域 | `/learn-domain --category=... --name=... --source=...` |
| 测试 | `/test --project=xxx` |
| 验收 | `/accept --project=xxx` |
| 反馈 | `/feedback --project=xxx --msg=...` |
| 关闭版本 | `/close --project=xxx` |
| 部署 | `/deploy --project=xxx` |
| 报告 | `/report --project=xxx --report-type=...` |
| 交付标注 | `/handoff --project=xxx` |
| 查看部署状态 | `/deploy --status` |

#### ❌ 不能做

| 操作 | 原因 |
|------|------|
| 查看/修改 `.codebuddy/configs/` | 流程引擎，管理员私有 |
| 查看/修改 `.codebuddy/scripts/` | 脚本工具，管理员私有 |
| 查看/修改 `.codebuddy/knowledge/common/` | 方法论知识库，管理员私有 |
| 修改 `deploy/` | 部署配置，管理员私有 |
| 修改其他成员的项目 | 只有自己的 `projects/{自己}/` 可写 |
| 直接编辑共享知识库 | 只能通过命令贡献，管理员审核后才可见 |

## 四、常见问题

### Q1：成员有多个项目怎么管理？

每个项目有独立的目录、端口、数据库。通过 `--project` 参数切换操作不同项目。可以同时在不同终端窗口开发不同项目。

### Q2：项目切换时数据会串吗？

不会。每个项目的 IndexedDB 数据库名不同（`{owner}-{project}-sim`），数据完全隔离。

### Q3：版本升级后数据还在吗？

在。同一项目不同版本共用同一个 IndexedDB 数据库，版本升级数据自动延续。

### Q4：部署失败怎么办？

部署失败不阻断版本冻结。执行 `/deploy --project=xxx --retry` 手动重试。

### Q5：换电脑怎么办？

```bash
git clone https://your-git-repo/pom-workspace.git
cd pom-workspace
git config user.name "zhangsan"
git config user.email "zhangsan@example.com"
cd projects/zhangsan/erp-portal && npm install
# 代码在 Git 中恢复，IndexedDB 数据新电脑重新初始化
```

### Q6：知识库贡献多久能审核完？

取决于管理员审核速度。提交 PR 后管理员收到通知，审核通过后立即对全员可见。

### Q7：Git 提交时不小心提交了其他人的文件怎么办？

```bash
# 撤销提交
git reset HEAD~1
# 只重新提交自己的文件
git add projects/zhangsan/erp-portal/
git commit -m "..."
```
