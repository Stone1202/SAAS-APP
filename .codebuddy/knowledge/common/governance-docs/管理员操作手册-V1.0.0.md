## 二、成员管理

### 2.1 注册新成员

```
步骤1：编辑 .access-control.yml
  members 下新增：
    - id: "lisi"
      name: "李四"
      git_name: "lisi"
      role: "member"
      active_project: "crm-portal"

步骤2：编辑 PROJECT-INDEX.yml
  members 下新增李四
  projects 下新增 crm-portal 项目（owner: lisi）

步骤3：分配端口（从端口池选空闲端口）
  port_pool.reserved 追加：
    - { owner: "lisi", project: "crm-portal", port: 4002 }

步骤4：EdgeOne 控制台创建访问账号

步骤5：通知成员：
  - Git 仓库地址
  - 访问门户 URL + 账号密码
  - CodeBuddy 使用说明（成员操作手册）
```

### 2.2 成员有多个项目

一个成员可以负责多个项目。为每个项目独立注册：

```
步骤1：编辑 PROJECT-INDEX.yml，在同一 owner 下新增项目
  projects:
    - id: "erp-portal"
      owner: "zhangsan"
      ...
      dev_port: 4001
      db_name: "zhangsan-erp-portal-sim"

    - id: "crm-portal"           # 新增第二个项目
      owner: "zhangsan"
      path: "projects/zhangsan/crm-portal"
      ...
      dev_port: 4002              # 分配新端口
      db_name: "zhangsan-crm-portal-sim"  # 新数据库名

步骤2：config.yml port_pool.reserved 追加新端口

步骤3：通知成员使用新项目名
  /init --project=crm-portal --type=新增 --desc=...
```

### 2.3 移除成员

```
步骤1：确认该成员的所有项目已关闭或转移
  → 检查 PROJECT-INDEX.yml 中该成员的项目状态
  → 如需转移，修改项目的 owner 字段

步骤2：编辑 .access-control.yml，移除该成员条目

步骤3：编辑 PROJECT-INDEX.yml，移除或标记该成员的项目为 inactive

步骤4：config.yml port_pool.reserved 移除该成员的端口

步骤5：EdgeOne 控制台禁用该成员的访问账号

步骤6：Git 平台移除该成员的仓库访问权限
```

### 2.4 权限调整

```
# 成员升级为管理员（如增设副管理员）
.access-control.yml 中修改 role: "member" → "admin"

# 管理员降级为成员
.access-control.yml 中修改 role: "admin" → "member"
```

## 三、多项目管理

### 3.1 项目注册清单

每个新项目需要配置以下内容：

| 配置项 | 文件 | 说明 |
|--------|------|------|
| 项目条目 | PROJECT-INDEX.yml | id/owner/path/name/stage/domain/dev_port/db_name/deploy |
| 端口分配 | config.yml port_pool.reserved | 从4000-4099中选空闲端口 |
| 部署配置 | deploy/edgeone-pages.json | 新增项目级路由配置 |
| 骨架创建 | ensure-project.sh | `bash .codebuddy/scripts/ensure-project.sh {owner} {project}` |

### 3.2 项目状态监控

```bash
# 查看所有项目状态
/cat .codebuddy/knowledge/PROJECT-INDEX.yml

# 查看部署状态
/deploy --status

# 查看所有项目骨架完整性
bash .codebuddy/scripts/ensure-project.sh jojo AI-SCRM --check
bash .codebuddy/scripts/ensure-project.sh zhangsan erp-portal --check
```

### 3.3 项目归档

```
项目不再活跃时：
  1. PROJECT-INDEX.yml 中项目 status 改为 "archived"
  2. 释放端口（port_pool.reserved 移除）
  3. EdgeOne 控制台可选保留或删除部署
  4. 项目代码保留在 Git 历史中
```

## 五、Git维护

### 5.1 分支策略

```
main（稳定分支）
  ├── 管理员维护流程引擎和部署配置
  ├── 成员的 PR 合并到此分支
  ├── CODEOWNERS 控制各目录的审批权
  └── 禁止直接 push，必须 PR + 审批

成员分支（开发分支）
  ├── 命名规范：{owner}/{project}-v{version}
  ├── 示例：zhangsan/erp-portal-v1
  ├── 成员在自己的分支上开发
  └── 开发完成后 PR 合并到 main

管理员分支（流程维护分支）
  ├── 命名规范：admin/{change-description}
  ├── 示例：admin/fix-port-allocation
  ├── 管理员在分支上修改流程配置
  └── 修改完成后 PR 合并到 main
```

### 5.2 CODEOWNERS 维护

```
# CODEOWNERS — 控制各目录的合并审批权
# 新增成员时在此追加

# === 流程引擎（仅 admin） ===
.codebuddy/configs/           @jojo
.codebuddy/scripts/           @jojo
.codebuddy/knowledge/common/  @jojo
deploy/                       @jojo
.access-control.yml           @jojo

# === 项目代码（各自 owner） ===
projects/jojo/                @jojo
projects/zhangsan/            @zhangsan
projects/lisi/                @lisi

# === 共享知识库（admin 审核） ===
.codebuddy/knowledge/domains/     @jojo
.codebuddy/knowledge/common/经验库/  @jojo
```

新增成员时：在 CODEOWNERS 中追加 `projects/{member}/  @{member}`。

### 5.3 定期维护操作

#### 每周维护

```bash
# 1. 检查 main 分支健康
git checkout main && git pull origin main

# 2. 清理已合并的分支
git branch --merged main | grep -v main | xargs git branch -d

# 3. 检查待处理的 PR
# 在 Git 平台查看 pending PRs

# 4. 检查部署状态
/deploy --status

# 5. 检查项目骨架完整性
for proj in AI-SCRM erp-portal; do
  bash .codebuddy/scripts/ensure-project.sh jojo $proj --check
done
```

#### 每两周反馈处理

```bash
# 1. 创建反馈处理分支
git checkout -b admin/feedback-20260728

# 2. 收集并分析反馈（见第四章）

# 3. 实施修改
# ... 修改配置文件 ...

# 4. 本地测试
bash .codebuddy/scripts/ensure-project.sh jojo AI-SCRM --check

# 5. 提交并推送
git add .codebuddy/configs/ .codebuddy/scripts/
git commit -m "fix: 反馈处理 20260728

- 修复端口分配未检测已占用
- 新增 BR 模板
- 部署后门户自动更新"

git push origin admin/feedback-20260728

# 6. 创建 PR → 审批 → 合并到 main

# 7. 通知成员拉取最新代码
# 在群内通知：main 分支已更新，请 git pull
```

#### 每月版本同步

```bash
# 1. 更新流程版本变更总账
# 追加本月所有变更记录

# 2. 更新记忆库
# 通过 update_memory 记录本月重要变更

# 3. 检查知识库贡献积压
/approve-knowledge --list
# 及时审核成员贡献

# 4. 归档已完成的项目版本
# PROJECT-INDEX.yml 中标记已完成的项目状态
```

### 5.4 版本同步到所有成员

当管理员修改了流程配置后，需要通知所有成员同步：

```
通知模板：
┌─────────────────────────────────────────────┐
│  📢 流程更新通知                              │
│                                               │
│  更新日期：2026-07-28                        │
│  更新内容：                                   │
│    1. 修复端口分配未检测已占用问题            │
│    2. 新增 BR 模板                           │
│    3. 部署后门户自动更新                      │
│                                               │
│  同步操作：                                   │
│    git checkout main                         │
│    git pull origin main                      │
│                                               │
│  如有问题请联系管理员。                       │
└─────────────────────────────────────────────┘
```

### 5.5 冲突处理

```
# 成员的 PR 与 main 有冲突时：
# 1. 成员在自己的分支上 rebase
git checkout zhangsan/erp-portal-v1
git fetch origin
git rebase origin/main

# 2. 解决冲突（只保留自己项目的文件）
# 3. 强制推送自己的分支
git push origin zhangsan/erp-portal-v1 --force-with-lease

# 4. PR 自动更新，等待审批合并
```

```json
{

    "jojo-ai-scrm": { ... },

      "owner": "zhangsan",

      "output_directory": "dist",

        "VITE_MODE": "sim"

      "routes": [
        { "src": "/zhangsan/erp-portal/(.*)", "dest": "/$1" }

    }
  }
}
```

## 七、知识库审核

### 7.1 审核流程

```bash
# 查看待审核清单
/approve-knowledge --list

# 审核通过（文件从 _pending/ 移到正式区）
/approve-knowledge --id=zhangsan_trade_交易通用_v1

# 审核驳回
/approve-knowledge --id=zhangsan_trade_交易通用_v1 --reject --reason="缺业务流程部分"

# 批量审核通过
/approve-knowledge --batch --all
```

### 7.2 审核标准

| 维度 | 检查项 |
|------|--------|
| 格式规范 | YML 结构符合 _TEMPLATE.yml |
| 内容完整 | 5部分（业务泳道+流程+信息流+操作矩阵+解决方案）齐全 |
| 来源可信 | 来源 URL/文件可追溯 |
| 无冲突 | 与已有领域知识不重复不矛盾 |
| 敏感信息 | 无客户数据/密钥/内幕信息 |

### 7.3 审核记录

每次审核后记录到 problem-ledger 或 Journal：

```
2026-07-28 知识库审核：
  ✅ zhangsan_trade_交易通用_v1 — 通过，质量良好
  ❌ zhangsan_payment_退款流_v1 — 驳回，缺状态机定义
```

## 八、流程版本升级

### 8.1 何时升级

- 收集到足够的反馈需要修改流程时
- 新增功能需要调整配置时
- 发现 Bug 需要修复时

### 8.2 升级流程

```
① 创建修改分支：git checkout -b admin/{change-description}
② 修改配置文件
③ 本地测试验证
④ 提交 PR → 审批 → 合并到 main
⑤ 更新流程版本变更总账
⑥ 更新记忆库（update_memory）
⑦ 通知所有成员拉取最新代码
⑧ （可选）触发全局深度检查
```

### 8.3 版本号规则

| 变更类型 | 版本号 | 示例 |
|---------|--------|------|
| 重大升级 | 主版本+1 | V5.0→V6.0 |
| 功能增强 | 次版本+1 | V5.0→V5.1 |
| 缺陷修复 | 补丁+1 | V5.0.0→V5.0.1 |
| 术语统一 | 补丁+1 | V5.0.0→V5.0.1 |

## 九、管理员速查卡

### 日常操作

| 场景 | 操作 |
|------|------|
| 注册新成员 | 编辑 .access-control.yml + PROJECT-INDEX.yml + CODEOWNERS |
| 检查项目状态 | `/deploy --status` + `ensure-project.sh --check` |
| 审核知识库 | `/approve-knowledge --list` → 通过/驳回 |
| 手动部署 | `/deploy --project=xxx` |
| 查看部署状态 | `/deploy --status` |

### 定期维护

| 频率 | 操作 |
|------|------|
| 每周 | 清理分支 + 检查PR + 检查部署状态 |
| 每两周 | 收集反馈 + 分析分类 + 实施修改 + 发布同步 |
| 每月 | 更新变更总账 + 更新记忆库 + 检查知识库积压 |

### 紧急操作

| 场景 | 操作 |
|------|------|
| 部署失败 | `/deploy --project=xxx --retry` |
| 成员无法访问 | 检查 .access-control.yml + EdgeOne 访问保护 |
| 项目骨架损坏 | `bash .codebuddy/scripts/ensure-project.sh {owner} {project}` |
| 回滚配置 | 从 .codebuddy/_backup/ 恢复 |
