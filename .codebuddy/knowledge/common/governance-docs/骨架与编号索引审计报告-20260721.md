## 三、编号体系问题（核心发现）

### 3.1 当前编号格式

| 编号类型 | 当前格式 | 含项目前缀 | 多项目冲突 |
|----------|----------|:---:|:---:|
| FN | `FN-{系统缩写}-{终端缩码}-{NNN}` | ❌ | **冲突** |
| UC | `UC-{系统缩写}-{终端缩码}-{NNN}-{SS}` | ❌ | **冲突** |
| PG | `PG-{系统缩写}-{终端缩码}-{NNN}` | ❌ | **冲突** |
| MD | `MD-{系统缩写}-{NNN}` | ❌ | **冲突** |
| SC | `SC-{系统缩写}-{NNN}` | ❌ | **冲突** |
| ENT | `ENT-{系统缩写}-{NNN}` | ❌ | **冲突** |
| BR | `BR-{系统缩写}-{NNN}` | ❌ | **冲突** |
| CONFIG | `CONFIG-{系统缩写}-{NNN}` | ❌ | **冲突** |
| METRIC | `METRIC-{系统缩写}-{NNN}` | ❌ | **冲突** |
| BG | `BG-{PREFIX}-{NNN}` | ✅ | 不冲突 |
| BO | `BO-{PREFIX}-{NNN}` | ✅ | 不冲突 |

**问题**：只有 BG/BO 含项目前缀（PREFIX），其余9类编号仅靠"系统缩写"区分。不同项目完全可以使用相同系统缩写（如两个项目都有 OPS 运营平台），导致编号冲突。

### 3.2 冲突场景示例

```
jojo/AI-SCRM 项目：
  FN-OPS-PC-001  → 客户管理功能
  UC-OPS-PC-001-01  → 新增客户用例

zhangsan/erp-portal 项目：
  FN-OPS-PC-001  → 订单管理功能  ← 编号相同！
  UC-OPS-PC-001-01  → 创建订单用例  ← 编号相同！

→ 跨项目检索、审计、handoff回传时无法区分
```

### 3.3 修复方案：编号增加项目前缀

**建议格式**（与 BG/BO 保持一致）：

| 编号类型 | 修复后格式 | 示例 |
|----------|-----------|------|
| FN | `FN-{PREFIX}-{系统缩写}-{终端缩码}-{NNN}` | FN-ACRM-OPS-PC-001 |
| UC | `UC-{PREFIX}-{系统缩写}-{终端缩码}-{NNN}-{SS}` | UC-ACRM-OPS-PC-001-01 |
| PG | `PG-{PREFIX}-{系统缩写}-{终端缩码}-{NNN}` | PG-ACRM-OPS-PC-001 |
| MD | `MD-{PREFIX}-{系统缩写}-{NNN}` | MD-ACRM-OPS-001 |
| SC | `SC-{PREFIX}-{系统缩写}-{NNN}` | SC-ACRM-OPS-001 |
| ENT | `ENT-{PREFIX}-{系统缩写}-{NNN}` | ENT-ACRM-OPS-001 |
| BR | `BR-{PREFIX}-{系统缩写}-{NNN}` | BR-ACRM-OPS-001 |
| CONFIG | `CONFIG-{PREFIX}-{系统缩写}-{NNN}` | CONFIG-ACRM-OPS-001 |
| METRIC | `METRIC-{PREFIX}-{系统缩写}-{NNN}` | METRIC-ACRM-OPS-001 |
| BG | `BG-{PREFIX}-{NNN}` | BG-ACRM-001（不变） |
| BO | `BO-{PREFIX}-{NNN}` | BO-ACRM-001（不变） |

**PREFIX 定义**：每个项目在 PROJECT-INDEX.yml 中注册时指定项目前缀（如 AI-SCRM=ACRM, erp-portal=ERP）。

## 四、门禁正则问题

### 4.1 当前门禁（过于宽松）

| 门禁 | 当前正则 | 问题 |
|------|---------|------|
| G-REQ-01 FN | `FN-.*-\d{3}` | `.*` 匹配任意，不校验系统缩写和终端缩码 |
| G-REQ-02 UC | `UC-.*-\d{3}` | 不校验子序号SS |
| G-REQ-07 BR | `BR-.*-\d{3}` | 不校验系统缩写 |
| G-REQ-13 BG/BO | `BG-\|BO-` | 仅检查字符串出现，不校验格式 |

### 4.2 建议升级正则

| 门禁 | 升级后正则 | 说明 |
|------|-----------|------|
| G-REQ-01 FN | `FN-[A-Z]{2,6}-(PC\|APP\|MINI\|H5\|PAD\|DSK)-\d{3}` | 严格校验终端缩码 |
| G-REQ-02 UC | `UC-[A-Z]{2,6}-(PC\|APP\|MINI\|H5\|PAD\|DSK)-\d{3}-\d{2}` | 校验子序号 |
| G-REQ-07 BR | `BR-[A-Z]{2,6}-\d{3}` | 校验系统缩写长度 |

## 五、state.json 问题

### 5.1 当前问题

```json
{
  "project": "AI-SCRM",          // ❌ 无owner维度
  "streams": [{
    "id": "STR-001",              // ❌ 无项目前缀，跨项目冲突
    "version": "v1.0.0",          // 版本号本身不冲突（路径隔离）
    "prd_version": "v1.0.1",      // ⚠️ 与version不同步
    "po_planning_version": "v2.0.0"  // ⚠️ 与version版本号混淆
  }]
}
```

### 5.2 建议修复

```json
{
  "project": "AI-SCRM",
  "owner": "jojo",               // ✅ 新增owner字段
  "project_prefix": "ACRM",      // ✅ 新增项目前缀
  "streams": [{
    "id": "STR-ACRM-001",        // ✅ 含项目前缀
    "version": "v1.0.0",
    "prd_version": "v1.0.1",
    "po_planning_version": "v2.0.0"
  }]
}
```
