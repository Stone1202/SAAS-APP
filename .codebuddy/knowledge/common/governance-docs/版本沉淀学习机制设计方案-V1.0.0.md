# 版本沉淀学习机制设计方案（V1.0.0）

> **文档定位**：`/close` 后自动将本次版本的需求、Review、经验教训学习沉淀到知识库，在项目和版本维度形成可复用的知识资产。
> **版本**：V1.0.0 | **日期**：2026-07-16
> **对齐**：POM V4.0.0

---

## 一、问题与目标

### 1.1 当前痛点

| 症状 | 根因 |
|------|------|
| 版本 close 后，需求/Review/经验散落在 `projects/{project}/` 下，知识库（`.codebuddy/knowledge/`）不感知 | `/close` 只做冻结+校验，无沉淀动作 |
| 下一版本 `/init` 只能加载 `/learn` 产出的 PRD，无法加载上一版本的实际开发经验 | 知识库无版本维度，无法按版本检索 |
| Review 报告产出后仅存 Journal，未提取可复用的经验教训 | Review 报告是"过程记录"，非"知识资产" |
| 跨项目经验无法复用（A 项目踩的坑，B 项目还会踩） | 知识库无"经验库"层，只有"需求文档"层 |

### 1.2 设计目标

```
/close 后自动执行：
  ① 需求沉淀 → 本次版本的 REQ 产物归入知识库（项目+版本维度）
  ② Review 沉淀 → 7 份 Review 报告提取经验教训归入知识库
  ③ 经验提炼 → PM 提炼可复用的经验教训（跨项目）
  ④ 版本索引 → 更新项目知识库的版本索引，后续版本可检索
  ⑤ 跨版本加载 → 下一版本 /init 时自动加载上一版本沉淀的知识
```

## 三、沉淀触发与执行流程

### 3.1 触发时机

```
/close 校验全部通过后 → PM 自动执行版本沉淀（无需用户触发）
```

**前置条件**（全部满足才沉淀）：
- ✅ 该流 stage = closed
- ✅ PBL 全部闭环（含跨版本传递已标记）
- ✅ 7 份 Review 报告全部产出且通过
- ✅ 追溯链完整性校验通过

## 四、Review 经验提炼规则

### 4.1 提炼维度

PM 从 7 份 Review 报告中按以下维度提炼：

| 维度 | 提炼内容 | 输出位置 |
|------|----------|----------|
| **反复问题** | 多个阶段 Review 中重复出现的问题（如"状态机不完整"在BA+QA+AC都出现） | 踩坑记录.md + Review模式库.md |
| **最佳实践** | Review 中标注"做得好"的部分（如"交互卡五段完整，值得推广"） | 最佳实践.md + 最佳实践库.md |
| **阶段薄弱点** | 哪个阶段 Review 问题最多（统计） | lessons-learned.yml |
| **跨阶段一致性** | 上下游阶段 Review 结论是否一致 | lessons-learned.yml |
| **Review 质量** | Review 报告本身的深度和准确性 | lessons-learned.yml |

### 4.2 Review 经验提炼模板

```markdown
# Review 经验提炼 — {project} {version}

## 一、反复问题模式

### 模式1：状态机不完整
- 出现阶段：BA Review / QA Review / AC Review
- 问题描述：PRD 状态机缺少 XX 状态
- 根因分析：需求阶段状态枚举不充分
- 改进建议：BA 阶段 state-enumerator 强制覆盖所有分支
- 避雷标签：#状态机 #需求完整性

### 模式2：...
```

## 五、下一版本 `/init` 的知识加载

### 5.1 加载逻辑升级

```
/init 时 PM 执行知识加载：

  ① 已有：加载 .codebuddy/knowledge/projects/{project}/需求文档/（/learn 产物）
  
  ② 已有：加载跨版本传递 PBL（上一版本未闭环反馈）
  
  ③ 🆕 新增：加载上一版本沉淀
     - 扫描 版本沉淀/VERSION-INDEX.yml
     - 取最近 N 个版本的沉淀摘要
     - 加载为 BA 需求分析输入：
       × 上一版本的 PRD（作为基线参考）
       × 上一版本的 Review 经验提炼（避免重复踩坑）
       × 上一版本的 lessons-learned（复用最佳实践）
       × 上一版本的上下游影响矩阵（影响范围参考）
  
  ④ 🆕 新增：加载经验库
     - 加载 经验库/最佳实践库.md（跨版本最佳实践）
     - 加载 经验库/踩坑避雷库.md（跨版本踩坑记录）
     - 加载 经验库/Review模式库.md（常见Review问题模式）
     → 作为所有阶段的背景知识
```

### 5.2 知识加载优先级

```
优先级从高到低：
  1. 跨版本传递 PBL（必须处理）
  2. 上一版本 Review 经验提炼（避免重复踩坑）
  3. 上一版本 PRD（基线参考）
  4. /learn 产出的 PRD（原始需求）
  5. 经验库（跨版本通用经验）
```

### 6.1 经验库层级

```

  ├── {project-A}/版本沉淀/    # 项目A的版本沉淀（项目内复用）
  ├── {project-B}/版本沉淀/    # 项目B的版本沉淀
  │
  └── common/                   # 跨项目通用知识

      │   ├── 最佳实践库.md     # 所有项目的最佳实践
      │   ├── 踩坑避雷库.md     # 所有项目的踩坑记录
      │   └── Review模式库.md   # 所有项目的Review问题模式
      │
      └── ...
```

### 6.2 跨项目复用触发

```
/init 时：
  PM 检查 .codebuddy/knowledge/common/经验库/
  若存在 → 加载为全阶段背景知识
  
  场景示例：
  - 项目A踩过"秒杀限流状态机不完整"的坑
  - 项目B做秒杀时 /init 自动加载踩坑避雷库
  - BA 在需求分析阶段就规避这个坑
```

## 七、沉淀质量校验

### 7.1 沉淀完整性检查

`/close` 沉淀完成后，PM 自动校验：

| 检查项 | 校验内容 | 不通过处理 |
|--------|----------|------------|
| 需求沉淀完整 | PRD + 产物体系 + 模块清单 + 影响矩阵 | 阻止 close，补齐后重试 |
| Review 沉淀完整 | 7 份 Review 报告 + 经验提炼 | 阻止 close |
| 经验教训已提炼 | lessons-learned + 最佳实践 + 踩坑 | 警告（不阻止） |
| 追溯链已快照 | traceability.yml | 阻止 close |
| 版本索引已更新 | VERSION-INDEX.yml 新增条目 | 阻止 close |
| 沉淀摘要已生成 | 沉淀摘要.md | 警告 |

### 7.2 沉淀质量评分

PM 对本次沉淀自动评分（0-100），写入 VERSION-INDEX.yml：

```yaml
sediment_quality:
  score: 85
  dimensions:
    requirements_completeness: 90   # 需求完整性
    review_depth: 80                # Review深度
    lessons_actionability: 85       # 经验可操作性
    traceability_coverage: 90       # 追溯覆盖
    cross_version_value: 75         # 跨版本复用价值
```

## 八、与现有机制的关系

| 现有机制 | 沉淀机制的关系 |
|----------|---------------|

| 跨版本反馈传递 | 沉淀的"经验教训"也是一种"跨版本传递"，但是知识层面 |
