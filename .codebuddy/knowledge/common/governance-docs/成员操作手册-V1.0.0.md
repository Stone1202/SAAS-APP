# 多人多项目 — 成员操作手册（V1.0.0）

> **适用对象**：使用 CodeBuddy + POM 流程的团队成员
> **前置条件**：方案已实施完成，管理员已完成基础配置
> **版本**：V1.0.0 | **日期**：2026-07-21

---

## 一、角色说明

| 角色 | 谁来担任 | 做什么 |
|------|---------|--------|
| **管理员** | 你（Jojo） | 维护流程引擎、注册成员、审核知识库、管理部署 |
| **技术成员** | 开发/产品技术 | 使用 CodeBuddy 命令走完整 POM 流程，开发自己的项目 |
| **产品成员** | 产品/运营/设计 | 不使用 CodeBuddy，只通过链接查看部署的高保真原型 |

## 二、技术成员操作说明

### 2.1 首次入驻（一次性）

#### 管理员先做（你操作）

```
步骤1：注册成员
  → 编辑 .access-control.yml，添加成员信息
  → 编辑 PROJECT-INDEX.yml，添加成员+项目条目
  → 系统自动分配端口（如 4001）

步骤2：创建访问账号
  → EdgeOne 控制台创建成员的访问账号密码

步骤3：通知成员
  → 告知：Git 仓库地址 + 访问门户账号密码
```

#### 成员做（如张三）

```bash
# 1. 克隆工作空间
git clone https://your-git-repo/pom-workspace.git
cd pom-workspace

# 2. 配置 Git 身份
git config user.name "zhangsan"
git config user.email "zhangsan@example.com"

# 3. 安装依赖（首次）
cd projects/zhangsan/erp-portal   # 如果项目骨架已由管理员创建
npm install

# 4. 打开 CodeBuddy，开始使用
```

> **验证**：在 CodeBuddy 中输入任意命令（如 `/report --type=status`），AI 会自动识别你的身份和项目。

### 2.2 日常开发流程

#### 场景A：新项目从零开始

```
步骤1：学习项目需求（如有现有文档）
  /learn-project --project=erp-portal --source=local-dir:./需求文档

  → CodeBuddy 学习文档，产出 PRD 存入 projects/zhangsan/erp-portal/docs/

步骤2：学习领域知识（可选，贡献到共享知识库）
  /learn-domain --category=trade --name=交易通用 --source=http-url:https://...

  → 产出存入 knowledge/domains/_pending/（待管理员审核）
  → 审核通过后全员可读

步骤3：启动需求流
  /init --project=erp-portal --type=新增 --desc=ERP门户v1.0

  → CodeBuddy 自动创建项目骨架（如不存在）
  → 分配端口、生成 .env 配置
  → 启动 BA 需求分析

步骤4：走完 POM 流程
  需求(BA) → 设计(UX) → 架构(Arch) → 开发(FD) → 测试(QA) → 验收(AC) → handoff

  → 每个阶段有专家 Review
  → 每个阶段可 /feedback 回流

步骤5：版本冻结 + 自动部署
  /close --project=erp-portal

  → 自动执行：
    ① 版本快照（Git Tag + build:sim）
    ② 版本沉淀学习（经验提炼到共享知识库，待审核）
    ③ 自动部署到 EdgeOne Pages
    ④ 输出访问链接

  → 你会看到：
    ┌──────────────────────────────────────────────┐
    │  ✅ 部署成功                                  │
    │  访问URL: https://xxx.edgeone.app/zhangsan/  │
    │           erp-portal/v1.0.0/                 │
    │  耗时: 45s                                   │
    └──────────────────────────────────────────────┘

步骤6：提交代码
  git add projects/zhangsan/erp-portal/
  git commit -m "feat(erp-portal): v1.0.0 完成"
  git push origin zhangsan/erp-portal-v1
  → 在 Git 平台创建 PR → 等待审批 → 合并到 main
```

#### 场景B：迭代已有项目

```
# 上一版本 /close 后，PM 会自动询问 PO 下一版本规划
# 形成递归闭环：

/init --project=erp-portal --type=迭代

  → CodeBuddy 自动加载上一版本沉淀 + 经验库
  → BA 基于 PO Backlog 进行需求分析
  → 继续 POM 流程...
  → /close → 自动部署 v2.0.0
```

#### 场景C：修复 Bug

```
/init --project=erp-portal --type=修复 --desc=修复客户列表分页问题

  → 跳过需求/设计/架构，直接进入开发(FD) → 测试(QA) → 验收(AC)
  → /close → 自动部署 v1.0.1
```

### 2.3 日常开发态

```bash
# 启动本地开发服务器（端口已自动分配，如 4001）

# → 浏览器打开 http://localhost:4001

npm run dev:real

# 构建仿真原型

```

### 2.4 成员能做什么 / 不能做什么

#### ✅ 能做

| 操作 | 命令 |
|------|------|
| 脑暴 | `/brainstorm --brainstorm-type=regular --project=erp-portal` |
| 启动需求 | `/init --project=erp-portal --type=新增 --desc=...` |
| 学习项目 | `/learn-project --project=erp-portal --source=...` |
| 学习领域 | `/learn-domain --category=... --name=... --source=...` |
| 测试 | `/test --project=erp-portal` |
| 验收 | `/accept --project=erp-portal` |
| 反馈 | `/feedback --project=erp-portal --msg=...` |
| 关闭版本 | `/close --project=erp-portal` |
| 报告 | `/report --project=erp-portal --report-type=...` |
| 交付标注 | `/handoff --project=erp-portal` |

#### ❌ 不能做

| 操作 | 原因 |
|------|------|
| 查看/修改 `.codebuddy/configs/` | 流程引擎，管理员私有 |
| 查看/修改 `.codebuddy/scripts/` | 脚本工具，管理员私有 |
| 查看/修改 `.codebuddy/knowledge/common/` | 方法论知识库，管理员私有 |
| 修改 `deploy/` | 部署配置，管理员私有 |
| 修改其他成员的项目 | 只有自己的 `projects/{自己}/` 可写 |
| 直接编辑共享知识库 | 只能通过命令贡献，管理员审核后才可见 |

## 三、产品成员操作说明

产品成员不使用 CodeBuddy，只查看部署结果。

### 3.1 访问高保真原型

```
步骤1：打开访问门户
  → 浏览器输入 https://xxx.edgeone.app/
  → EdgeOne 访问保护弹出登录框
  → 输入管理员分配的账号密码

步骤2：查看项目版本
  → 访问门户列出所有已部署的项目版本
  → 按 成员 → 项目 → 版本 组织

  ┌─────────────────────────────────────────────────┐
  │  POM 部署运营门户                  👤 当前: viewer │
  ├─────────────────────────────────────────────────┤
  │  👤 jojo (管理员)                                 │
  │    📦 AI-SCRM                                    │
  │       └─ v1.0.0  [访问] [差异报告] [PRD快照]      │
  │                                                   │
  │  👤 zhangsan (成员)                               │
  │    📦 erp-portal                                  │
  │       └─ v1.0.0  [访问] [差异报告] [PRD快照]      │
  └─────────────────────────────────────────────────┘

步骤3：点击 [访问] 查看高保真原型
  → 原型完全可交互（仿真模式）
  → 数据存储在浏览器 IndexedDB 中（本地，不影响他人）
  → 可正常增删改查，刷新后数据保留
```

### 3.2 版本对比

```
点击 [差异报告]
  → 查看两个版本之间的差异
  → 页面清单变化（新增/修改/删除）
  → 用例清单变化
  → 数据结构变化
  → 三种查看模式：单版本 / 差异高亮 / 并排对比
```

### 3.3 产品成员能做什么 / 不能做什么

#### ✅ 能做
- 查看所有已部署的高保真原型
- 查看版本差异报告
- 查看 PRD 快照
- 在原型中操作（增删改查数据，本地存储）

#### ❌ 不能做
- 修改原型代码
- 执行 CodeBuddy 命令
- 查看其他成员的源代码
- 修改部署配置

## 四、管理员操作说明

### 4.1 注册新成员

```
步骤1：编辑 .access-control.yml
  members 下新增：
    - id: "lisi"
      name: "李四"
      git_name: "lisi"
      role: "member"
      active_project: "crm-portal"

步骤2：编辑 PROJECT-INDEX.yml
  members 下新增李四
  projects 下新增 crm-portal 项目（owner: lisi, dev_port: 4002, db_name: lisi-crm-portal-sim）

步骤3：EdgeOne 控制台创建访问账号

步骤4：通知李四：Git 仓库地址 + 访问门户账号密码
```

### 4.2 审核知识库贡献

```bash
# 查看待审核清单
/approve-knowledge --list

# 审核通过
/approve-knowledge --id=zhangsan_trade_交易通用_v1

# 审核驳回
/approve-knowledge --id=zhangsan_trade_交易通用_v1 --reject --reason="缺业务流程部分"
```

### 4.3 管理部署

```bash
# 手动部署（如自动部署失败后重试）
/deploy --project=AI-SCRM

# 查看部署状态
/deploy --status --project=AI-SCRM

# 查看所有部署清单
# 直接查看 deploy/DEPLOY-MANIFEST.yml
```

## 五、常见问题

### Q1：成员本地开发时端口冲突怎么办？

**A**：每个项目有独立端口（自动从 4000-4099 分配），写在 `.env.development` 的 `VITE_DEV_PORT` 中。如遇端口被占用：

```bash
# 查看分配的端口
cat projects/zhangsan/erp-portal/.env.development | grep VITE_DEV_PORT

# 如需修改，联系管理员在 PROJECT-INDEX.yml 中重新分配
```

### Q2：成员的 IndexedDB 数据会和其他人串吗？

**A**：不会。每个项目的数据库名不同：
- jojo 的 AI-SCRM → `jojo-ai-scrm-sim`
- 张三的 erp-portal → `zhangsan-erp-portal-sim`
- 数据完全隔离，互不影响

### Q3：同一项目升级版本后数据还在吗？

**A**：在。同一项目不同版本共用同一个 IndexedDB 数据库，版本升级数据自动延续。例如 AI-SCRM v1.0.0 → v2.0.0，你在 v1 添加的客户数据在 v2 中依然存在。

### Q4：部署失败怎么办？

**A**：`/close` 时部署失败不阻断版本冻结。可手动重试：
```bash
/deploy --project=erp-portal
```
如持续失败，联系管理员检查 EdgeOne Pages 配置。

### Q5：成员能看到其他人的项目吗？

**A**：
- **代码层面**：Git 仓库中能看到（Monorepo 模式），但 CODEOWNERS 阻止修改别人的项目
- **知识层面**：共享知识库（domains/ + 经验库）全员可读
- **部署层面**：访问门户能看到所有已部署版本（如管理员授权）

### Q6：成员贡献的领域知识多久能审核完？

**A**：取决于管理员审核速度。成员提交后管理员会收到 PR 通知，审核通过后立即对全员可见。未审核前只在 `_pending/` 目录，其他成员看不到。

### Q7：产品团队怎么提反馈？

**A**：两种方式：
1. **通过技术成员**：告知技术成员，技术成员用 `/feedback --msg=...` 提交
2. **通过访问门户**：在原型中操作发现问题 → 截图发给对应技术成员

### Q8：成员换了电脑怎么办？

**A**：
```bash
# 新电脑上重新克隆
git clone https://your-git-repo/pom-workspace.git
cd pom-workspace
git config user.name "zhangsan"
git config user.email "zhangsan@example.com"

# 项目代码在 Git 中，克隆即恢复
# IndexedDB 数据在浏览器中，新电脑需重新初始化（首次访问自动种子数据）
```
