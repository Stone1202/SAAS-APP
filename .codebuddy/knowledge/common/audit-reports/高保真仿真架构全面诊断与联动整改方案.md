# 高保真仿真架构全面诊断与联动整改方案

> **文档定位**：PM + 架构师 + POM 三方联合诊断，针对可插拔仿真架构调整，全面覆盖项目骨架、配置、流程、Agent 的联动整改方案。
> **日期**：2026-07-16
> **参与方**：PM Agent（互联网项目管理专家）、Arch Agent（高保真前端开发架构师）、POM 宪法 V4.0.0

## 一、终极目标重申

```
高保真仿真原型 = 未来生产级前端基座

客户试用仿真原型（sim模式）→ 确认通过 → 切换 real 模式 → 前端零修改 → 后端可插拔（FastAPI/Django/Node.js/Go）
```

**架构核心要求**：
1. 契约驱动：Zod Schema 定义接口，sim 和 real 共用契约
2. 五维可插拔：data/transport/stream/asset/auth 独立切换
3. 业务规则归位：Service 层承载业务逻辑，UI/Store 零业务逻辑
4. 环境变量驱动：VITE_MODE=sim|real，支持按模块覆盖
5. 开箱即用：提供后端示例 + 对接指南
6. 契约校验：运行时 Zod 校验，sim/real 响应不符契约立即报错

### 3.2 架构师核心诊断结论

**当前架构的根本问题**：项目骨架是"脚手架模板"级别（scaffolds/ 下占位代码），不是"可运行的可插拔架构"。

具体表现：
1. **无根级构建配置**：没有 package.json / vite.config.ts / tsconfig.json，项目无法 `npm install && npm run dev`
2. **契约层空壳**：contracts/ 目录存在但 schemas/ 为空，无 Zod 定义
3. **Adapter 层缺失**：scaffolds/ 有模板但不是五维可插拔的 adapter 架构
4. **Service 层缺失**：业务规则没有归位到独立 Service 层
5. **无单元测试**：没有测试架构，无法保证 sim/real 契约一致性
6. **无后端示例**：客户无法开箱即用

```typescript
// tests/contract-consistency/order-contract.test.ts
// 核心测试：sim 和 real 返回的数据结构必须完全一致

import { describe, it, expect } from 'vitest';
import { SimOrderRepository } from '@/adapters/sim/repositories/SimOrderRepository';
import { CreateOrderRequestSchema, CreateOrderResponseSchema } from '@/contracts/schemas/order-contract';

describe('Order Contract Consistency', () => {
  it('sim 返回的响应符合 Zod Schema', async () => {
    const repo = new SimOrderRepository();
    const result = await repo.create({ product_id: 'P001', quantity: 1, address_id: 'A001' });
    expect(() => CreateOrderResponseSchema.parse(result)).not.toThrow();
  });

  it('sim 返回的错误码在枚举范围内', async () => {
    const repo = new SimOrderRepository();
    try {
      await repo.create({ product_id: 'NOT_EXIST', quantity: 1, address_id: 'A001' });
    } catch (e) {
      expect(e.code).toBe('PRODUCT_NOT_FOUND');
    }
  });
});
```
