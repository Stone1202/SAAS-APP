# 跨项目踩坑避雷库

> 本文件由 knowledge-sedimentation.yml 在每次 /close 后自动追加。
> 所有项目的踩坑记录汇聚于此，供其他项目 /init 时加载避雷。

## 格式规范

每条踩坑记录包含：
- **来源**：项目名 + 版本号
- **阶段**：BA/UX/Arch/FD/QA/AC
- **坑点标题**：一句话概括
- **现象**：发生了什么
- **根因**：为什么会发生
- **解决方案**：如何修复
- **预防措施**：其他项目如何避免

## 踩坑记录

### 1. Playwright connectOverCDP 连接 Android WebView 失败

- **来源**：SAAS项目 / 真实系统端到端验收
- **阶段**：QA（验收）
- **坑点标题**：Playwright connectOverCDP 对 Android WebView 不兼容
- **现象**：`connectOverCDP` 报错 `Browser context management is not supported`
- **根因**：Android WebView 的 CDP 实现不完整，browser 级 CDP 不支持上下文管理（setDownloadBehavior 等方法不存在）
- **解决方案**：改用原生 WebSocket（ws库）直连页面级 CDP，绕过 browser 级连接
- **预防措施**：移动端 WebView 的 CDP 验收不要用 Playwright connectOverCDP，直接用 ws 库 + CDP 协议

### 2. chrome-remote-interface 库连接 Android WebView 失败

- **来源**：SAAS项目 / 真实系统端到端验收
- **阶段**：QA
- **坑点标题**：chrome-remote-interface 报 socket hang up
- **现象**：用 `CDP({ target: webSocketDebuggerUrl })` 连接时 `socket hang up`
- **根因**：chrome-remote-interface 内部有额外 HTTP 请求逻辑，与 Android WebView 的 CDP 实现不兼容
- **解决方案**：用 `ws` 库直连 WebSocket，手动实现 CDP 协议（JSON 命令/响应）
- **预防措施**：Android WebView CDP 连接优先用原生 ws 库，不用第三方封装库

### 3. release 包不开启 WebView 调试

- **来源**：SAAS项目 / 真实系统端到端验收
- **阶段**：QA
- **坑点标题**：release APK 没有 webview_devtools_remote socket
- **现象**：`adb shell cat /proc/net/unix | grep webview_devtools_remote` 无输出
- **根因**：release 包代码里 `WebView.setWebContentsDebuggingEnabled(false)`，不创建调试 socket
- **解决方案**：`adb root` + `adb shell setprop debug.webview.dev true`，强制全局开启 WebView 调试，重启 APP 后 socket 出现
- **预防措施**：root 模拟器上可用 setprop 强制开启；非 root 设备需找研发要 debug 包

### 4. WebView 调试 socket 名称带进程 PID

- **来源**：SAAS项目
- **阶段**：QA
- **坑点标题**：socket 名称是 webview_devtools_remote_<PID>，每次启动变化
- **现象**：端口转发到固定名称 `webview_devtools_remote` 失败
- **根因**：Android WebView 的调试 socket 名称包含进程 PID，每次启动 PID 不同
- **解决方案**：动态查找 `adb shell cat /proc/net/unix | grep -oE 'webview_devtools_remote_[0-9]+'`
- **预防措施**：不要硬编码 socket 名称，始终动态查找

### 5. CDP Input.dispatchMouseEvent 不触发 Vue @click

- **来源**：SAAS项目
- **阶段**：QA
- **坑点标题**：坐标点击不触发 uni-app Vue 事件
- **现象**：CDP `Input.dispatchMouseEvent` 点击了正确坐标，但页面没跳转
- **根因**：uni-app 的 Vue @click 绑定的是 DOM click 事件，CDP 的 mousePressed/mouseReleased 不等同于 click 事件
- **解决方案**：用 `Runtime.evaluate` 执行 `element.click()` 直接触发 DOM click 事件
- **预防措施**：uni-app/Vue 页面的点击用 `element.click()`，不用坐标点击

### 6. APP 启动后只有 View 层页面

- **来源**：SAAS项目
- **阶段**：QA
- **坑点标题**：CDP 连到了 View 层而非业务页面
- **现象**：连接后 `hasText` 返回 false，页面内容为空
- **根因**：APP 刚启动时只有 View 层页面（title=View），业务页面（title=pages/index/index）还没加载
- **解决方案**：轮询等待 `pages/` 页面出现（最多10次，每次2秒）
- **预防措施**：连接 CDP 后先检查页面 title 是否包含 `pages/`，没有就等待

### 7. CDP Runtime.evaluate 返回值路径

- **来源**：SAAS项目
- **阶段**：QA
- **坑点标题**：evaluate 返回 undefined
- **现象**：`evaluate('document.title')` 返回 undefined
- **根因**：CDP 返回格式是 `{ result: { result: { type, value } } }`，send 方法返回 `msg.result`，需要再取 `.result.value`
- **解决方案**：evaluate 方法返回 `result?.result?.value`（双层 result）
- **预防措施**：封装 CDP 客户端时注意返回值层级，写测试用例验证

### 8. 后台 Naive UI drawer 遮挡菜单

- **来源**：SAAS项目
- **阶段**：QA
- **坑点标题**：抽屉组件挡住侧边栏菜单点击
- **现象**：点击"交易"菜单超时，错误信息显示 `n-drawer-container subtree intercepts pointer events`
- **根因**：上一步操作（发布商品）弹出的抽屉没关闭，遮罩层挡住了菜单
- **解决方案**：操作前先 `page.keyboard.press('Escape')` 关闭可能存在的抽屉
- **预防措施**：Naive UI 后台操作前先 ESC 关闭弹窗，再导航菜单
