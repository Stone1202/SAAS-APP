# 跨项目最佳实践库

> 本文件由 knowledge-sedimentation.yml 在每次 /close 后自动追加。
> 所有项目的最佳实践汇聚于此，供其他项目 /init 时加载参考。

## 格式规范

每条最佳实践包含：
- **来源**：项目名 + 版本号
- **阶段**：BA/UX/Arch/FD/QA/AC
- **实践标题**：一句话概括
- **详细描述**：做法+效果
- **复用建议**：其他项目如何应用

## 最佳实践记录

### 1. 真实系统跨端验收：Playwright + 原生WebSocket CDP 方案

- **来源**：SAAS项目 / 真实系统端到端验收
- **阶段**：QA（验收）
- **实践标题**：用 Playwright 操控后台Web + 原生WebSocket CDP 操控 uni-app APP，实现跨端端到端验收
- **详细描述**：
  - 后台Web用 Playwright launch 启动浏览器操控（标准方案）
  - APP端用 ws 库直连 WebView 的页面级 CDP（绕过 Playwright connectOverCDP 兼容性问题）
  - 跨端数据通过 SharedDataContext 共享（用商品ID/订单号做跨端锚点）
  - 后端API直查作为兜底（拿"系统真相"验证数据真实落库）
  - APK反编译提取页面路由+API清单作为验收依据（95个API+80页路由）
- **复用建议**：详见 `common/qa/e2e-acceptance-guide.md`，代码模板在 `e2e-acceptance/` 目录

### 2. adb root + setprop 强制开启 WebView 调试

- **来源**：SAAS项目
- **阶段**：QA
- **实践标题**：在 root 模拟器上用 setprop 强制开启 release 包的 WebView 调试
- **详细描述**：`adb root` → `adb shell setprop debug.webview.dev true` → 重启APP，release 包也会创建 webview_devtools_remote socket
- **复用建议**：Android 模拟器默认支持 root，所有需要 CDP 验收 release 包的场景都适用

### 3. APK 反编译提取验收依据

- **来源**：SAAS项目
- **阶段**：QA
- **实践标题**：unzip APK → 提取 uni-app 前端资源 → 获取页面路由和API清单
- **详细描述**：APK 本质是 ZIP，uni-app 前端资源在 `assets/apps/__UNI__XXXX/www/`，从 `app-config-service.js` 提取80页路由，从 `app-service.js` grep 提取95个API接口
- **复用建议**：无文档的旧项目验收，反编译APK是获取验收依据的最快途径

### 4. clickNearbyText 锚点附近点击

- **来源**：SAAS项目
- **阶段**：QA
- **实践标题**：在商品列表中点击"某商品"对应的"购买"按钮
- **详细描述**：用 TreeWalker 找到锚点文字（商品名），向上遍历找容器，在容器内找目标文字（购买按钮），用 `element.click()` 触发
- **复用建议**：列表型页面中点击特定项的操作按钮，比坐标点击更可靠

### 5. 跨端验收三端协同框架

- **来源**：SAAS项目
- **阶段**：QA
- **实践标题**：后台Web(Playwright) + APP(CDP) + 后端(API直查) 三端协同验收
- **详细描述**：一个验收用例内同时持有三个"遥控器"，按业务流程顺序操作，用共享数据传递ID，每步做数据一致性断言，后端直查作为兜底真相
- **复用建议**：所有跨端联动场景（下单/分享/扫码/退款）都适用此框架
