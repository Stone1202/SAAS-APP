## 二、系统架构概览

百货商城是一个 **SaaS 私域直播电商** 系统，采用"门店后台 + 小程序 C 端 + 供应商端"三层架构：

```
┌─────────────────────────────────────────────────────┐
│                    百货商城 SaaS                       │
├─────────────────┬─────────────────┬─────────────────┤
│   店长后台        │   小程序 C 端     │   供应商端        │
│  (Web 管理端)     │  (微信小程序)     │  (审核/收货)      │
├─────────────────┼─────────────────┼─────────────────┤
│ • 商品管理        │ • 首页/分类页      │ • 退货审核        │
│ • 订单管理        │ • 商品详情         │ • 确认收货        │
│ • 发货管理        │ • 我的订单         │                  │
│ • 售后管理        │ • 店铺订单         │                  │
│ • 退款审核        │ • 包裹物流         │                  │
│ • 门店退货物流    │ • 售后详情         │                  │
│ • 退货返厂        │ • 福利券           │                  │
│ • 调拨管理        │ • 地址配置         │                  │
│ • 库存管理        │                   │                  │
│ • 数据报表        │                   │                  │
│ • 交易相关        │                   │                  │
│ • 系统配置        │                   │                  │
└─────────────────┴─────────────────┴─────────────────┘
```

## 三、核心业务流程

1. **商品交易闭环**：商品管理 → 小程序浏览 → 下单 → 支付 → 发货 → 收货
2. **售后处理闭环**：申请售后 → 店长审核 → 退货退款 → 退货物流（供应商协同）
3. **供应商协同**：门店退货物流 → 供应商审核/收货 → 退货返厂
4. **游客转化漏斗**：游客浏览提审商品 → 注册登录 → 绑定门店 → 完整商品可见

## 四、核心业务规则摘要

| 规则 | 简述 |
|------|------|
| BR-MALL-001 | 退货地址智能判断：自提订单按配置判断门店/供应商地址，快递到家订单判断供应商/平台地址 |
| BR-MALL-002 | 物流填写控制：自提订单按配置显隐填写入口，快递到家强制填写 |
| BR-MALL-003 | 待收货入口由后台配置项控制显隐 |
| BR-MALL-005 | 多物流单号按包裹独立展示，支持「全部」聚合视图 |
| BR-MALL-006 | 游客/未绑定用户展示提审分类商品，限制只能购买快递到家商品 |

## 五、问题与建议

### 5.1 原型本身的问题

| # | 问题 | 严重程度 | 建议 |
|---|------|----------|------|
| 1 | 部分页面标注"需UI出图"（库存管理、调拨管理、退货返厂），缺少最终视觉稿 | 中 | 后续开发前需确认 UI 设计稿 |
| 2 | 库存管理存在两个文件：`库存管理.html` 和 `库存管理【需ui出图】.html`，存在版本歧义 | 中 | 以标注"需UI出图"版本为准 |
| 3 | 未登录_未绑定展示商品中存在已作废逻辑（到店自提提示已划删除线） | 低 | 开发时需忽略作废逻辑 |
| 4 | 原型中大量纯 UI 渲染数据（Axure 组件坐标），不含实际业务字段定义 | 低 | PRD 中的数据实体基于业务逻辑推断，实际字段以数据库设计为准 |
| 5 | 缺少支付、物流对接、消息推送等三方接口的详细规格 | 高 | 需补充接口文档 |
| 6 | 多版本并存（v1_0_1 ~ v1_6_1），缺乏版本差异说明 | 中 | 建议补充 CHANGELOG |

### 5.2 功能缺口

| # | 缺口 | 影响 | 建议 |
|---|------|------|------|
| 1 | 缺少完整的权限模型定义（操作员角色页面仅包含角色名称，无具体权限矩阵） | 高 | 需补充 RBAC 权限设计 |
| 2 | 缺少营销模块（优惠券、满减、秒杀等） | 中 | 后续迭代规划 |
| 3 | 缺少直播电商相关功能（直播间商品关联、直播下单等） | 中 | 与"私域直播电商"定位相关，建议评估优先级 |
| 4 | 数据报表仅含页面截图，缺少具体统计维度和指标定义 | 中 | 需补充报表需求明细 |
