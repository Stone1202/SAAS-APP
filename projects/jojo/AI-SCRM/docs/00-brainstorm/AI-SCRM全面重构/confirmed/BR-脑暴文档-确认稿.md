## 二、核心决策（14项）

| 编号 | 决策 | 选择 | 理由 |
|------|------|------|------|
| D1 | 架构模式 | 双系统独立部署 | 运营后台是独立SAAS商业引擎，非附属管理页 |
| D2 | AI定位 | 可选增强层（非系统必备） | 不订阅AI=传统SCRM完整可用；专业版+才有AI能力 |
| D3 | 租户数据隔离 | 逻辑隔离（共享DB+tenant_id） | 初期租户数量可控，后期可平滑升级到混合隔离 |
| D4 | 权限模型 | RBAC + 数据域权限 + 字段级权限 | 2B销售团队管理需要精细数据隔离 |
| D5 | 终端策略 | PC优先 → 移动H5 → 移动APP | 渐进式覆盖 |
| D6 | SAAS管理 | 运营后台独立模块 | 废弃 v1.0.0 D6（降级到系统设置） |
| D7 | 行业模板 | 预置式（4行业×6维度） | 降低租户上手成本 |
| D8 | AI引擎 | Coze（主）+ 火山引擎（备） | 多厂商防锁定 |
| D9 | 版本付费模式 | 月付/年付 + 资源包叠加 | SAAS标准商业模式 |
| D10 | 运营工具 | 健康度评分 + 分层运营 | 精细化租户运营 |
| D11 | AI用量计费 | 按Token/按调用次数 | 透明可核算 |
| D12 | 移动端交付 | H5先行（P3），原生APP随后（P4） | 降低初期成本 |
| D13 | 传统SCRM模块 | 完整保留（客户/沟通/待办/SOP/数据看板） | 非AI版核心价值 |
| D14 | 运营后台交付 | 与租户后台同步P1-P2交付 | 商业模式完整性 |

## 九、v3.0.0 深度修正：SOP重新定义（2026-07-18）

### 9.1 问题诊断

v1.0.0/v2.0.0 将 SOP 定义为「流程编排、自动执行、状态追踪」——这是**照抄传统SCRM的抽象概念**，没有真正理解其业务本质。

**真正的问题是**：销售人员每天面对客户时，需要什么实际帮助？

### 9.2 SOP 的真实业务本质

SOP 不是一个独立的功能模块，而是**嵌入在「一条客户沟通」全过程中的 AI 辅助闭环**：

```
                              ┌── 成交 ↑
                              ├── 复购 ↑
沟通中（实时AI辅助）            ├── 客户粘性 ↑
┌─────────────────────────┐    ├── 满意度 ↑
│ ① 话术推荐              │    │
│    基于上下文+画像       │    │
│    匹配最佳回复话术      │    │
│                         │    │
│ ② 情绪监控              │    │
│    实时情绪曲线          │    │
│    负面波动预警          │    │
│                         │    │
│ ③ 商品推荐              │    │
│    识别客户交易意向      │    │
│    匹配最可能成交商品    │    │
│                         │    │
│ ④ 意图识别              │    │
│    客户意图：买/比价/    │    │
│    顾虑/不感兴趣/投诉    │    │
└──────────┬──────────────┘    │
           ↓                   │
沟通后（AI自动处理）            │
┌─────────────────────────┐    │
│ ⑤ 沟通总结              │    │
│    聊了什么、决定了什么    │    │
│    哪里做得好、哪里可改进  │    │
│                         │    │
│ ⑥ 画像更新              │    │
│    从对话中提取标签      │    │
│    丰富客户画像          │    │
│                         │    │
│ ⑦ 跟进生成              │    │
│    基于意向安排跟进任务  │    │
│    员工意图→画像/跟进    │    │
└──────────┬──────────────┘    │
           ↓                   │
持续跟进                        │
┌─────────────────────────┐    │
│ 待办 → 日历排程 →        │    │
│ 执行 → 再沟通 →          │    │
│ 循环...                  │    │
└─────────────────────────┘    │
                               ▼
                    最终目的：成交+复购+粘性+满意
```

### 9.3 双意图识别

| 意图类型 | 识别内容 | 触发动作 |
|----------|----------|----------|
| **客户意图**（交易意向） | 想买 / 在比价 / 有顾虑 / 不感兴趣 / 有投诉 | 高意向→推荐商品+促成话术；比价→对比话术；顾虑→打消顾虑话术；投诉→情绪预警+主管介入 |
| **员工意图**（跟进意图） | 该丰富标签 / 该安排跟进 / 该推什么产品 | 画像不完整→自动补标签；需跟进→自动生成待办+排日历；适合推荐→匹配商品 |

### 9.4 模块体系修正

v2.0.0 的 17 模块体系中，「SOP引擎」和「AI智能体」是两个独立抽象模块。
v3.0.0 修正：去掉这两个抽象模块，替换为**嵌入业务流程的具体能力**。

| v2.0.0（旧） | v3.0.0（新） | 说明 |
|-------------|-------------|------|
| SOP引擎（流程编排+自动执行+状态追踪） | ❌ 删除 | 能力分散到「统一沟通」和「AI沟通辅助」中 |
| AI智能体（智能回复+自动处理链+智能排程） | ❌ 删除 | 拆解为「AI沟通辅助」的具体能力 |
| — | **统一沟通**（新增） | 企微聊天+电话+短信+邮件 统一入口 + 沟通记录 |
| — | **AI沟通辅助**（新增） | 沟通中4项（话术/情绪/商品/意图）+ 沟通后4项（总结/质检/画像/跟进） |
| — | **跟进管理**（新增） | 统一待办中心+跟进日历+销售漏斗 |
| 客户管理 | 客户管理（保留） | 增强为包含360视图+分群 |
| 待办任务 | → 合并到跟进管理 | — |
| 沟通中心 | → 合并到统一沟通 | — |
