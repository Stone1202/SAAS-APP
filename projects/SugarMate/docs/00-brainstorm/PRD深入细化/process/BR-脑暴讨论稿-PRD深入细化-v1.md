## 一、讨论基础

### 1.1 产品定位回顾

SugarMate = 小程序获客引流 → APP承接深度服务 → 业务后台管控运营  
覆盖：科普教育 / 在线问诊 / 电子处方 / 电商购药 / CGM监测 / 饮食运动 / 患者社区

### 1.2 当前规模

| 维度 | 数量 |
|------|------|
| FN功能 | 70（MP×8 / APP×42 / PC×12 / SCRM×8） |
| P0 | 44（63%） |
| 参与者 | 16类 |
| 外部API | 13个 |
| 场景 | 61个（S01-S61） |

### 1.3 本轮讨论目标

1. **逐业务域深入审查**：每个闭环的FN完整性、UC合理性、规则一致性
2. **模糊点澄清**：PRD中写「待定」、未明确的地方
3. **边界交叉问题**：多系统/多角色交叉场景是否有遗漏
4. **分期策略建议**：70个FN是否合理？是否需要分期？
5. **技术可行性预判**：哪些功能依赖外部条件需要提前确认

### 3.3 状态机完整性

当前状态机覆盖了「患者全病程」，但缺少以下状态机：
- 📌 **问诊订单状态机**：待支付→待接诊→接诊中→已完成/已取消/已退款
- 📌 **处方状态机**：草稿→待审核→审核中→已审核/已驳回→已失效
- 📌 **订单状态机**：待支付→已支付→已发货→运输中→已签收→已完成→(售后中→已退款)
- 📌 **商家状态机**：待审核→审核中→已通过/已驳回→已激活→已冻结
- 📌 **会员状态机**：免费→付费→已过期→续费中

### 3.4 优先级与分期

当前70个FN，P0占63%（44个），直接全量上线风险很高：
- 问诊+处方+购药是核心商业闭环，必须首批
- SCRM是获客转化前提，需要首批
- 社区/直播/CGM可作为第二批
- 建议明确V1.0 / V1.1 / V2.0分期边界
