## 1. 端到端业务流转全景

### 1.1 三终端角色矩阵

| 终端 | 角色 | 职责 |
|------|------|------|
| **APP** | 患者 | 选择医生→下单→等待→对话→查处方→收推荐→评价 |
| **APP** | 医生 | 接诊→问诊对话→开处方→完结→查收入 |
| **APP** | 签约用户 | 免下单直达问诊（通过包月权益） |
| **小程序** | 患者 | 复用APP核心流程（共享Store+契约，仅UI适配） |
| **PC后台** | 管理员 | 审核服务→监控问诊→数据漏斗→纠纷仲裁 |

### 1.3 端到端一致性约束矩阵

| 一致性维度 | 约束规则 | 验证方式 |
|-----------|----------|---------|
| **状态流转一致性** | SM-CON-01 的所有状态过渡在三个终端展示一致 | 状态机→页面状态映射表 |
| **信息一致性** | 处方/档案/订单/消息在同一时刻三终端数据一致 | Adapter→Store→Page单向数据流 |
| **场景闭环一致性** | 10个E2E场景的每一步在页面层都有对应可操作入口 | E2E验收矩阵 |
| **端一致性** | APP患者→APP医生→PC后台的同一订单数据完全一致 | 共享Store+同一Adapter |
| **契约一致性** | 所有页面表单/按钮/展示基于同一组Zod Schema衍生 | Zod→Form schema→UI |
| **仿真一致性** | Sim数据通过IndexedDB持久化，跨页面/跨终端共享 | IndexedDB读写验证 |

#### C2: SM-CON-01 状态机（SM-16增强版）

```
18个状态：
SERVICE_CREATED → PAID → PENDING_ACCEPT → ACCEPTED → IN_CONSULT
→ PENDING_PRESCRIPTION → PRESCRIPTION_ISSUED → PRESCRIPTION_CONFIRMED
→ PRESCRIPTION_FLOWING → WAITING_PATIENT_CONFIRM → PATIENT_CONFIRMED
→ RECOMMENDATION_SHOWN → COMPLETED → EVALUATED
←─ 异常分支 ─→
→ TIMEOUT_REFUNDING → REFUNDED
→ DISPUTING → ARBITRATING → PARTIAL_REFUNDED → WITHDRAWN
```

#### C3: SM-03 处方状态机修正

```
修正前（7状态）:
DRAFT → SUBMITTED → CA_SIGNED → REVIEWED → PATIENT_AGREED → FLOWING → DISPENSED

修正后（8状态）:
DRAFT → SUBMITTED → CA_SIGNED → REVIEWED
→ AWAITING_PATIENT_CONFIRM  ← 新增节点
   ├─ patient_confirm → PATIENT_AGREED
   ├─ patient_reject → DRAFT（医生修改重提）
   └─ patient_timeout(72h) → EXPIRED
→ FLOWING → DISPENSED
```

**状态过渡操作表（SM-03修正版核心变更）**：

| 当前状态 | 触发操作 | 目标状态 | 操作者 | 前置约束 | 后置动作 |
|----------|---------|----------|--------|---------|---------|
| PENDING_AUDIT | 审核通过 | AWAITING_PATIENT_CONFIRM | 药师 | BR-CON-006所有必填项完整 | 推送患者·启动72h定时器 |
| AWAITING_PATIENT_CONFIRM | patient_confirm | PATIENT_AGREED | 患者 | 已阅读处方详情+用药说明 | 资金托管→医生分账·处方可流转 |
| AWAITING_PATIENT_CONFIRM | patient_reject | DRAFT | 患者 | 提供拒绝原因 | 通知医生·处方回到草稿可修改 |
| AWAITING_PATIENT_CONFIRM | timeout_72h | EXPIRED | 系统 | 72h未操作 | 通知医患双方·资源释放 |

```
SV4 档案授权:
  ├─ 首次问诊→引导创建档案
  ├─ 授权时效：单次问诊有效/30天有效/永久
  ├─ CGM数据关联：自动拉取7天血糖摘要
  └─ 字段级控制：脱敏摘要(首次) vs 完整档案(授权后)
```

## 6. 信息流一致性设计

### 6.1 统一数据实体生命周期

```
ConsultationOrder
  id: UUID
  serviceOrderId: SM-16(共享)
  patientId / doctorId
  status: SM-CON-01状态
  messages: ConsultationMessage[]
  prescription: Prescription? (关联)
  evaluation: Evaluation?
  recommend: PostConsultRecommend[]
  archiveAuthorization: ArchiveAuthorization?
  createdAt / updatedAt / timeoutAt
```

### 6.2 三终端数据同步机制

```
[Sim模式]: IndexedDB 'consultation-sim' 数据库
  ├─ consultationStore 读写 IndexedDB
  ├─ APP患者、APP医生、PC后台共享同一数据库
  ├─ 任一终端修改 → Store自动提交 → 其他终端重新查询即获最新数据
  └─ 仿真时间线：修改记录 timestamp，支持时间旅行调试

[Real模式]: REST API + WebSocket
  ├─ /api/consult/* REST端点
  ├─ WebSocket实时消息推送
  └─ 离线队列+断线重连
```
