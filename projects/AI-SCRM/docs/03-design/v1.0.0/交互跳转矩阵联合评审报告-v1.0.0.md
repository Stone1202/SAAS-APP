## 维度1：多模块跳转 + 子页面穿插

**评估人**：UX设计师 + BA  
**输入**：交互跳转矩阵（第8章）+ 信息结构（第2章）+ BA业务流程图

### D1-a：跨模块路由合理性

| 检查项 | 判定 | 详情 |
|--------|:--:|------|
| 模块间跳转是否有明确业务语义 | ✅ 通过 | 每条跳转均有清晰业务语义，如「客户详情→统一沟通（关联客户）」明确传递了客户上下文 |
| 跨模块跳转是否携带足够的上下文 | ✅ 通过 | PG-TNT-PC-003→PG-TNT-PC-005 携带客户ID和关联信息，PG-TNT-PC-001→PG-TNT-PC-009待办筛选参数透传 |
| 跨模块跳转深度是否≤3层 | ✅ 通过 | 最深路径：首页→客户列表→客户详情→统一沟通（3步），恰好≤3层 |

### D1-b：子页面穿插评估

| 检查项 | 判定 | 详情 |
|--------|:--:|------|
| 同一模块子页面跳转路径最短 | ✅ 通过 | 如「沟通记录列表→沟通记录详情」直接跳转，无中间页 |
| 是否存在循环跳转 | ✅ 通过 | 无 A→B→A 循环跳转 |
| 是否存在孤立页面 | ✅ 通过 | 全部23页面在导航树中均有入口，全部13弹窗均有触发元素 |
| 子页面穿插是否与BA流程图一致 | ✅ 通过 | 跳转顺序与PRD五图中业务流程节点顺序一致 |

### D1-c：页面层级深度

| 深度 | 页面 | 判定 |
|:--:|------|:--:|
| 1步 | 工作台、客户列表、统一沟通、待办中心等（从侧边栏直达） | ✅ |
| 2步 | 客户详情、沟通记录详情、沟通分析看板、跟近日历等 | ✅ |
| 3步 | 统一沟通（经客户详情→发起沟通） | ✅ 边界值，但业务场景合理（先查看客户再发起沟通） |

> 评语：最深3步均为「客户详情→发起沟通」路径，属于合理的业务流程而非随意跳转。无 >3步的页面。

### D1-d：导航回溯能力

| 检查项 | 判定 | 详情 |
|--------|:--:|------|
| 每个跳转是否可通过面包屑/返回回溯 | ✅ 通过 | 1.1节明确定义「所有二级及以上页面显示面包屑导航」，顶层设计保证了全局回溯 |
