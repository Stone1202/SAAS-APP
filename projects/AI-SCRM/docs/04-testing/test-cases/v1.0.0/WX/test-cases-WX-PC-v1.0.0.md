# 测试用例 — 企微授权管理（WX）× PC

> 关联FN：FN-WX-PC-001~002 | 关联BR：BR-WX-001~006 | PRD v1.0.1 新增模块

## 功能用例

### TC-WX-PC-001：首次授权企微
- **优先级**：P0 | **类型**：功能用例 | **关联FN**：FN-WX-PC-001 | **关联BR**：BR-WX-001
- **前置条件**：企业管理员已登录，租户无已授权企微
- **步骤**：
  1. 系统设置 → 企微授权管理 → 显示空状态引导
  2. 点击「添加企微授权」→ 弹出OAuth引导页
  3. 确认授权权限（外部联系人读写、客户群读写、消息推送）
  4. 模拟企微回调 → 系统保存CorpID/CorpSecret/access_token
- **预期**：
  - 授权记录创建（ENT-TNT-011，状态=SYNCING→AUTHORIZED）
  - 同步启动：员工列表、外部联系人列表、客户群列表开始拉取

### TC-WX-PC-002：重复CorpID拦截
- **优先级**：P0 | **类型**：异常流程 | **关联FN**：FN-WX-PC-001 | **关联BR**：BR-WX-001
- **前置条件**：已存在CorpID=「ww123」的授权
- **步骤**：再次添加同一CorpID的授权
- **预期**：提示「该企微已授权，请查看已有授权」

### TC-WX-PC-003：access_token自动刷新
- **优先级**：P0 | **类型**：功能用例 | **关联FN**：FN-WX-PC-001 | **关联BR**：BR-WX-004
- **前置条件**：企微已授权，token有效期剩余3分钟
- **步骤**：等待token到期时间逼近
- **预期**：
  - 到期前5分钟自动刷新token
  - 新token和expires_at写入数据库
  - 旧token不再可用

### TC-WX-PC-004：企微授权过期处理
- **优先级**：P1 | **类型**：异常流程 | **关联FN**：FN-WX-PC-001
- **前置条件**：企微授权已过期（refresh_token也失效）
- **步骤**：
  1. 进入企微授权管理 → 列表显示「已过期」
  2. 点击「重新授权」→ 引导重新扫码
- **预期**：状态更新为「已过期」，可重新授权

### TC-WX-PC-005：员工通过企微添加客户
- **优先级**：P0 | **类型**：功能用例 | **关联FN**：FN-WX-PC-002 | **关联BR**：BR-WX-002
- **前置条件**：员工已绑定企微身份（wx_account_id+employee_id），客户王五存在
- **步骤**：
  1. 客户详情 → 点击「企微添加」
  2. 系统检查企微好友状态 → 显示「未添加」
  3. 展示添加引导（二维码/链接）
  4. 模拟企微回调 add_external_contact 事件
- **预期**：
  - ENT-TNT-013 创建好友关系记录（is_friend=true）
  - 客户页面显示「已添加企微好友」

### TC-WX-PC-006：邀请客户加入客户群
- **优先级**：P0 | **类型**：功能用例 | **关联FN**：FN-WX-PC-002 | **关联BR**：BR-WX-003
- **前置条件**：客户已是企微好友，企微下有客户群A（150/200人）
- **步骤**：
  1. 沟通页 → 选择客户 → 「邀请加入客户群」
  2. 系统展示可用客户群列表（群名、成员数、是否已满）
  3. 选择客户群A → 点击「邀请加入」
  4. 模拟企微回调 change_external_chat 事件
- **预期**：
  - 客户群A成员数更新为151
  - 客户in_groups数组追加group_id
  - 页面提示「已邀请加入客户群A」

## 流程用例

### TC-WX-PC-007：多企微账号并行管理
- **优先级**：P0 | **类型**：流程用例 | **关联FN**：FN-WX-PC-001 | **关联BR**：BR-WX-001~002
- **前置条件**：租户无授权
- **步骤**：
  1. 授权企微A（CorpID=ww111）→ 同步完成（客户100，群5）
  2. 授权企微B（CorpID=ww222）→ 同步完成（客户50，群3）
  3. 验证企微A和B的客户数据隔离
  4. 员工甲在企微A添加客户李四 → 员工乙在企微B添加同一客户李四
- **预期**：
  - 两条独立好友关系记录（add_way可能不同）
  - 客户「李四」在customer表中只有一条，但关联两个不同的企微账号

### TC-WX-PC-008：客户群满员防护
- **优先级**：P1 | **类型**：边界用例 | **关联FN**：FN-WX-PC-002 | **关联BR**：BR-WX-003
- **前置条件**：客户群B已满200人
- **步骤**：企微聊天 → 选择客户 → 选择客户群B → 邀请加入
- **预期**：提示「客户群已满（200/200），请选择其他群」

### TC-WX-PC-009：企微好友关系解除
- **优先级**：P1 | **类型**：流程用例 | **关联FN**：FN-WX-PC-002 | **关联BR**：BR-WX-006
- **前置条件**：客户与员工已有企微好友关系，存在沟通记录
- **步骤**：企微回调 del_external_contact 事件
- **预期**：
  - 好友关系标记为DELETED（非物理删除）
  - 历史沟通记录保留
  - 客户页面显示「企微好友已解除」

## 边界/异常

### TC-WX-PC-010：员工未绑定企微身份
- **优先级**：P0 | **类型**：异常用例 | **关联FN**：FN-WX-PC-002
- **步骤**：未绑定企微身份的销售坐席 → 进入客户详情 → 点击「企微添加」
- **预期**：提示「请先在企业微信授权管理中绑定你的企微账号」

### TC-WX-PC-011：企微API超时降级
- **优先级**：P1 | **类型**：异常用例 | **关联FN**：FN-WX-PC-002
- **步骤**：企微API不可用（模拟网络故障）
- **预期**：
  - 调用超时5秒 → 提示「企微服务暂不可用，请稍后重试」
  - 系统不崩溃，其他功能正常

### TC-WX-PC-012：客户群创建→解散全流程
- **优先级**：P2 | **类型**：流程用例 | **关联FN**：FN-WX-PC-002
- **步骤**：
  1. 员工在企微端创建客户群C
  2. 系统收到 change_external_chat 回调 → 创建群记录
  3. 群主解散客户群C → 系统收到回调 → 标记群为DISSOLVED
- **预期**：群生命周期完整追踪，解散后不从列表删除但显示「已解散」

### TC-WX-PC-013：回调事件去重
- **优先级**：P1 | **类型**：边界用例 | **关联FN**：FN-WX-PC-001 | **关联BR**：BR-WX-005
- **步骤**：模拟企微重复推送同一 add_external_contact 事件（相同callback_id）
- **预期**：只创建一条好友记录，不重复

### TC-WX-PC-014：企微授权数量无限制
- **优先级**：P2 | **类型**：边界用例 | **关联FN**：FN-WX-PC-001
- **步骤**：连续授权5个不同企微账号
- **预期**：5个均授权成功，列表正确展示，无性能衰减
