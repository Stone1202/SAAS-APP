## 2. 用例卡数据

### PG-AUDIT-PC-001 运营后台-租户审查开关

- **FN**: FN-AUDIT-PC-001 租户内容审查开关管理
- **UC**: UC-AUDIT-001
- **前置条件**: 平台运营已登录+腾讯云审核模板已配置
- **基本流程**:
  1. [手动] 进入租户审查开关页
  2. [系统自动] 展示租户列表（名称/行业/域名/开关/状态/违规/操作）
  3. [手动] 点击开关→弹出确认弹窗
  4. [手动] 确认→开关状态更新→中控室Tab显示/隐藏
  5. [手动] 可点击"进入中控"跳转
- **备选流程**: 关闭审查时提示"平台不可降级类仍强制执行"
- **数据范围(R/W)**: R:租户列表 W:审查开关状态
- **后置条件**: 租户审查开关生效
- **按钮标注**: BTN-005审查开关 / BTN-006进入中控

### PG-AUDIT-PC-002 租户后台-直播中控室

- **FN**: FN-AUDIT-PC-003 中控室内容审查Tab
- **UC**: UC-AUDIT-002
- **前置条件**: 场次状态为"直播中"+内容审查已开启
- **基本流程**:
  1. [系统自动] 中控室加载内容审查Tab
  2. [系统自动] 提示区展示实时告警（红/黄/蓝三级）+违规数+审查状态
  3. [系统自动] 违规列表展示（时间/类型/级别/敏感词/置信度/建议/擦音/状态/操作）
  4. [手动] 点击违规行查看详情
  5. [手动] 处置：记录/断流（二次确认）/忽略
  6. [系统自动] 处置结果更新状态+记录日志
  7. [手动] 切换擦音模式（静音/擦音）
- **备选流程**: 30秒未处置→系统自动记录+告警升级
- **数据范围(R/W)**: R:违规记录 W:处置记录
- **后置条件**: 违规处置完成+擦音模式生效
- **按钮标注**: BTN-001记录 / BTN-002断流 / BTN-003忽略 / BTN-004擦音模式 / BTN-007详情 / BTN-008回调JSON

### PG-AUDIT-APP-001 观众APP-直播间

- **FN**: FN-AUDIT-APP-001 观众直播间内容审查感知
- **UC**: UC-AUDIT-005
- **前置条件**: 观众已进入直播间+主播直播中+内容审查已开启
- **基本流程**:
  1. [系统自动] 展示直播画面+主播信息+弹幕+操作栏
  2. [事件驱动] 腾讯云检测违规并执行擦音
  3. [系统自动] 感知擦音效果：静音（🔇+进度条+画面变暗）/擦音（🎧+声波+嘀声）
  4. [系统自动] 弹幕展示违规过滤标记
  5. [事件驱动] 30%概率"中控室尚未收到回调"提示
  6. [事件驱动] 断流时显示"直播已结束，因内容违规已被终止"
- **备选流程**: 擦音模式由租户中控室配置，通过localStorage同步
- **数据范围(R/W)**: R:擦音模式(localStorage) W:无
- **后置条件**: 观众感知擦音效果+弹幕过滤+断流提示
- **按钮标注**: BTN-009切换擦音模式

> 用户审阅后如有变更，变更内容写入此处，回传BA增量重跑需求分析。

### 5.1 回传状态

| 项 | 值 |
|---|---|
| 回传状态 | ⏳ **待回传** |
| 用户审阅结果 | 等待用户在原型中审阅【？】用例卡 |
| 变更数量 | 待用户确认 |
| 回传BA | 待用户审阅完成后触发 |

### 5.2 回传规则（handoff.yml V4.1.0）

- 用户审阅后**有变更** → 变更写入回传区 → 回传BA → 增量重跑需求分析 → 重新/handoff（含代码注入）
- 用户审阅后**无变更** → 标记"确认无变更" → 可进入/close
- **在/close之前，状态始终为"待回传"**
