## 二、数量一致性

### 2.1 PRD 中的 FN / UC 定义

| 编号 | 名称 | 关联UC | 对应PG | 页面 |

### 2.2 UC 数量偏差

| 指标 | PRD | 原型 | 偏差 |
|------|-----|------|------|
| FN 总数 | 6 | 6（1 基础设施 + 5 页面） | ✅ 0 |
| UC 总数 | §17 声称为 5 | **0**（没有独立的 UC 交互用例卡） | ❌ -5 |
| FN→UC 关联数 | UC-AUDIT-001~004（4个）与§17说的5个矛盾 | 无 | ❌ PRD 自身矛盾 |
| 交互用例卡文件 | 无 | **0**（projects/SAAS/ 下未找到任何 instruction-card 文件） | ❌ |

### 2.3 结论

- **UC 不是独立产物**：PRD 中 UC 编号仅出现在 FN 表格的「关联UC」字段中，没有独立章节的六段标准格式（前置条件/基本流程/备选流程/数据范围/后置条件/关联UC）
- **PRD 自身矛盾**：§17摘要说"5 个 UC"，但 FN 关联字段只出现 4 个编号（UC-AUDIT-001~004），UC-AUDIT-005 不存在
- **交互用例卡缺失**：原型没有生成任何可独立交付的用例卡文件，PG 页面直接按 FN 实现，跳过了 UC 级产品抽象
- **根因**：BA 在 PRD 阶段没有产出完整的 UC 六段定义，导致后续 prototype-generator 无法基于 UC 生成用例卡片

### 5.3 审查开关联动链（严重缺陷）

PRD §5 定义了审查开关的核心联动链：

```
开关关闭 → 模拟回调不启动 → 直播列表不显示审查入口
        → 直播中控无审查Tab → 观众端无擦音效果 → 回放不触发擦音
```

**原型中这条联动链完全未实现。** 各页面之间通过 auditStore 共享状态，但 `tenantConfig.enabled` 的值并未用于控制：
- ❌ 直播列表的「审查」入口显示/隐藏
- ❌ 直播中控「审查」Tab 的显示/隐藏
- ❌ 观众端擦音效果的启用/禁用
- ❌ 回放擦音的触发条件

## 七、根因分析（Root Cause Analysis）

### 7.1 五层根因剖析

| 层级 | 问题 | 根因 |
|------|------|------|
| **L1 - UC 层缺失** | PRD 有 FN 无 UC，UC 编号仅存在于 FN 表格的「关联UC」字段，没有六段标准格式定义 | BA 在 PRD 阶段跳过了完整的 UC 六段格式，仅以「用户故事 US-AUDIT-001~007」替代 |
| **L2 - 设计断层** | 没有独立的 UX 设计文档（8 章强制结构），原型直接根据 PRD 文字描述做「可运行 MVP」，不是「1:1 还原」 | /init 流程中 UX 阶段未被完整执行，design-flow.yml §3-§7 产物缺失 |
| **L3 - 交互模式偏差** | «链接+弹窗» → «Switch 开关» 的模式变化源于 PRD 文字描述模糊 | PRD 对入口交互的描述是文字性的「操作列平铺链接」，没有 UI 线框图/代码标注，原型生成器自行选择了「更现代」的 Switch 组件 |
| **L4 - 联动链断裂** | 审查开关的 5 级联动仅在 PRD 中作为文字描述存在，不是可执行契约 | BR 的触发条件没有转化为代码级的条件分支，Store 中 `tenantConfig.enabled` 未被下游组件消费 |
| **L5 - 回放简化** | FN-AUDIT-PC-004 在原型中是「静态展示页」，PRD 要求的进度条/超时/失败/重试全部缺失 | 回放擦音需要异步任务模拟（setTimeout + 进度回调），开发复杂度高于其他 FN，原型生成器退化为静态展示 |

### 7.2 核心矛盾

```
PRD §5（开关联动链 5级）    → 纯文字描述，无 BR 编号绑定，无代码契约
PRD FN-AUDIT-PC-004 回放   → 5 个备选流程 + 3 个 BR（未转化为交互状态）
PRD UC-AUDIT-001~004       → 仅有编号，无六段内容（前置/流程/备选/数据/后置/关联）
                              ↓ 原型在无 UC 的情况下按 FN 做可运行版本
                              ↓ 结果：页面能做出来，但逻辑和交互大量缺失
```
