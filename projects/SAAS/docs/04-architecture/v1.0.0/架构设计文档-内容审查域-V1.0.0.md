## 第二章：架构总览

### 2.1 五层架构（自上而下）

```
┌──────────────────────────────────────────────┐
│  页面层 (Pages)                              │
│  运营后台 / 租户后台 / 观众端H5              │
├──────────────────────────────────────────────┤
│  组件层 (Components)                         │
│  通用组件 + 业务组件                         │
├──────────────────────────────────────────────┤
│  存储层 (Stores - Pinia)                     │
│  auditStore（违规/处置/擦音配置/状态共享）    │
├──────────────────────────────────────────────┤
│  服务层 (Services)                           │
│  auditService / replayService / mockGenerator │
├──────────────────────────────────────────────┤
│  适配器层 (Adapters - sim/real)              │
│  data / transport / stream / asset / auth     │
└──────────────────────────────────────────────┘
         ↕ 契约层 (Contracts - Zod)
         实体Schema / API契约 / 状态机
```

### 2.2 数据流

```
┌─────────────────────────────────────────────────────────────┐
│ [定时器] MockGenerator (SimAdapter)                          │
│    │ 每 5-15s 生成违规事件                                    │
│    ▼                                                        │
│ auditService.handleViolation(event)                          │
│    │ 1. 30%概率标记回调丢失                                   │
│    │ 2. 写入 auditStore.violations[]                          │
│    ▼                                                        │
│ auditStore (Pinia - 共享Store)                               │
│    │ $subscribe                                              │
│    ├──→ PC直播中控：追加违规列表 + 告警统计更新               │
│    └──→ H5观众端：触发擦音效果（静音/擦音动画）               │
│                                                              │
│ [用户操作] PC直播中控处置                                      │
│    │ 记录/断流/忽略                                           │
│    ▼                                                        │
│ auditService.handleDisposal(violationId, type, reason)       │
│    │ 更新 violation.disposal_status                           │
│    │ 若断流：场次状态 → 已结束，广播断流事件                   │
│    ▼                                                        │
│ auditStore → $subscribe → H5观众端显示"直播因违规已终止"      │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 路由规划（严格对齐 PRD §17「三终端路由/入口复用」）

**前缀规则**：`/admin/` = 运营后台 | `/tenant/` = 租户后台 | `/h5/` = 观众端

| 路由 | 终端 | 页面 | 关联FN | PRD §17 来源 |
|---|---|---|---|---|
| `/admin/audit-switch` | PC-运营后台 | 租户审查开关管理（PG-AUDIT-PC-001） | FN-AUDIT-PC-001 | PRD §17 行1 |
| `/tenant/dashboard` | PC-租户后台 | 直播列表入口模拟（PG-ENTRY-TENANT-001） | —（入口页，提供「更多」菜单） | PRD §17 入口复用要求 |

| `/tenant/replay/:streamId` | PC-租户后台 | 回放详情-擦音效果（PG-AUDIT-PC-003） | FN-AUDIT-PC-004 | PRD §17 行5 |

## 第三章：三层契约（C-A5）

### 3.1 实体Schema（Zod）

详见 `src/contracts/schemas/audit-schemas.ts`：
- `ReviewViolationSchema`（违规记录 — ENT-AUDIT-001）
- `ReviewDisposalSchema`（处置记录 — ENT-AUDIT-002）
- `TenantAuditConfigSchema`（租户审查配置 — ENT-AUDIT-003）
- `ReplayMuteTaskSchema`（回放擦音任务 — ENT-AUDIT-004）
- `ReplayFileSchema`（回放文件 — ENT-AUDIT-005）

### 3.2 API契约

详见 `src/contracts/api/audit-api.ts`：
- `POST /api/audit/switch` — 租户审查开关
- `GET /api/audit/violations/:liveId` — 获取违规列表
- `POST /api/audit/disposal` — 违规处置
- `GET /api/audit/replay/:liveId/mute-status` — 回放擦音状态

### 3.3 状态机

详见 `src/contracts/state-machine/audit-state-machine.ts`：

**场次状态机**：
```
直播中 ──[断流处置]──→ 已结束
直播中 ──[正常结束]──→ 已结束
已结束 ──[回放生成]──→ 回放中
```

**违规状态机**：
```
待处理 ──[记录]────→ 已记录
待处理 ──[断流]────→ 已断流
待处理 ──[忽略]────→ 已忽略
待处理 ──[30s超时]─→ 已超时
待处理 ──[审查关闭]─→ 已归档
```

## 第四章：Store架构

### 4.1 auditStore（Pinia Store）

```typescript
// 共享Store — PC直播中控 + H5观众端 共用
useAuditStore {
  // 状态
  violations: ReviewViolation[]        // 违规列表（实时追加）
  tenantConfig: TenantAuditConfig       // 租户审查配置
  muteMode: 'silent' | 'beep'          // 擦音/静音模式
  fieldStatus: 'live' | 'ended'        // 场次状态
  callbackLost: boolean                 // 当前是否有回调丢失
  replayTask: ReplayMuteTask | null     // 回放擦音任务

  // 计算属性
  alertStats: { l1: number, l2: number, l3: number, l4: number }
  pendingViolations: ReviewViolation[]
  filteredViolations(filter: FilterOptions): ReviewViolation[]

  // 操作
  appendViolation(v: ReviewViolation): void
  setMuteMode(mode: 'silent' | 'beep'): void
  disposeViolation(id: string, type, reason): Promise<void>
  setFieldStatus(status: 'live' | 'ended'): void
  startReplayMuteTask(streamId): Promise<void>
  reset(): void  // 清理（页面卸载时）
}
```

## 第七章：架构决策记录（ADR）

| ADR编号 | 决策 | 理由 | 替代方案 |
|---|---|---|---|
| ADR-001 | sim/real双适配器模式 | V1纯前端模拟，V2+对接腾讯云，适配器模式零修改切换 | 条件编译（侵入性强） |
| ADR-002 | 单一Pinia Store共享状态 | 直播中控+观众端需要实时共享违规数据，避免多Store同步问题 | EventBus（调试困难） |
| ADR-003 | Zod契约先行 | 运行时校验+类型推导，架构→FD→QA全链路一致性 | JSDoc注释（无运行时校验） |
| ADR-004 | Mock后端采用Python FastAPI | 与Vue前端解耦，便于后续替换为真实后端，团队Python技能 | Express.js（前端全栈一致性但V1策略不需要） |
| ADR-005 | Element Plus组件库 | PRD明确复用已有页面风格，SAAS项目全线使用Element Plus | Ant Design Vue（迁移成本） |
| ADR-006 | 前端直接模拟定时器+Store事件 | V1不需要任何后端，纯内存运行，降低依赖 | Mock Service Worker（额外依赖，过度设计） |
